# 처리 구조 — 논리 경계 초안

첫 PoC의 순수 Core 세션·이벤트 계약·로컬 저장을 구현했다. 서버·DB·Windows adapter·생성기는 없다. 아래 표는 전체 목표의 책임 분리이며 구현 완료 목록이 아니다.

| 처리 영역 | 책임 | 입력/출력 경계 |
|---|---|---|
| PC collector | 허용된 세션의 앱/화면/지원 동작 관찰 | OS 권한·대상 범위 → 순서·공백·로컬 근거 |
| local filter/review | 제외·마스크·수집 내용 확인 | 로컬 원본 → 허용된 이벤트/근거 |
| event ingestion | 순서·중복·유실·세션 상태 검증 | 이벤트 집합 → 재현 가능한 입력 버전 |
| draft generation | 허용 입력을 절차 초안·확인 질문으로 변환 | 고정 입력 → 생성 시도·출처 있는 초안 |
| revision/review | 수정·검수·근거 변경 영향 처리 | 대상 버전 → 새 버전·승인/반려 |
| export/retention | 허용 결과물·근거 보관·폐기 | 검수본/삭제 요청 → 결과와 처리 증거 |

UI 접근성 이벤트·스크린샷·영상의 지원 범위는 OS·앱마다 다르다. 수집 근거는 신뢰할 수 없는 입력으로 취급하고 화면의 명령을 시스템 지시로 실행하지 않는다. 자동 업무 수행 도구를 생성 모델에 제공하는 기능은 이번 범위에 포함하지 않는다.

로컬 우선과 수집기+서버 구조를 데이터량·외부 전송·비용·배포 제약으로 비교한 후 선택한다. 프록시·벡터 DB·큐·클라우드 서비스를 설치돼 있다는 이유만으로 제품 구조에 넣지 않는다.

## 첫 구현 분리 제안

[로컬 PoC 설계](superpowers/specs/2026-10-16-windows-local-poc-design.md)는 순수 Core와 Windows observer/capture/UI adapter를 분리한다. Core 상태/manifest/export는 Linux에서도 검증하고 실제 API·프레임·권한은 Windows 장비에서 검증한다. Core의 .NET10·로컬 메타데이터 저장은 구현·단위 검증했다. WPF/Windows 수집·manifest/export는 아직 구현되지 않았다. 기본 provider를 호출하지 않는 template 경로와 향후 실제 provider를 명시적으로 분리한다.

## Task1 구현 파일

`src/GhostManual.Core`는 Windows 참조와 외부 서비스 없이 net10.0으로 빌드된다. Session이 상태/허용 앱/순서/중복/20분 경과를 담당하고 CaptureEvent가 안전한 직렬화 경계를 담당한다. SessionStore는 잠금 안에서 상태를 복사한 뒤 불변 snapshot을 작성하고 포인터를 게시한다. UI 타이머·잠금 감지·전면 앱 Poll·이미지·생성·내보내기는 후속 구현이다. 세션 시간은 TimeProvider의 단조 경과 시간을 쓰므로 시스템 시각 변경으로 기록 시간이 늘어나지 않게 한다.
