# 처리 구조 — 논리 경계 초안

첫 PoC의 제품 코드·서버·DB는 없다. 데스크톱 기술·로컬/원격 배치·모델 제공자는 미정이며 아래는 책임 분리 제안이다.

| 처리 영역 | 책임 | 입력/출력 경계 |
|---|---|---|
| PC collector | 허용된 세션의 앱/화면/지원 동작 관찰 | OS 권한·대상 범위 → 순서·공백·로컬 근거 |
| local filter/review | 제외·마스크·수집 내용 확인 | 로컬 원본 → 허용된 이벤트/근거 |
| event ingestion | 순서·중복·유실·세션 상태 검증 | 이벤트 집합 → 재현 가능한 입력 버전 |
| draft generation | 허용 입력을 절차 초안·확인 질문으로 변환 | 고정 입력 → 생성 시도·출처 있는 초안 |
| revision/review | 수정·검수·근거 변경 영향 처리 | 대상 버전 → 새 버전·승인/반려 |
| export/retention | 허용 결과물·근거 보관·폐기 | 검수본/삭제 요청 → 결과와 처리 증거 |

UI 접근성 이벤트·스크린샷·영상의 지원 범위는 OS·앱마다 다르다. 수집 근거는 신뢰할 수 없는 입력으로 취급하고 화면의 명령을 시스템 지시로 실행하지 않는다. 자동 업무 수행 도구를 생성 모델에 제공하는 기능은 이번 범위에 포함하지 않는다.

로컬 우선과 수집기+서버 구조를 데이터량·외부 전송·비용·배포 제약으로 비교한 후 선택한다. 프록시·벡터 DB·큐·클라우드 서비스를 설치돼 있다는 이유만으로 제품 구조에 넣지 않는다.

## 첫 구현 분리 제안

[로컬 PoC 설계](superpowers/specs/2026-10-16-windows-local-poc-design.md)는 순수 Core와 Windows observer/capture/UI adapter를 분리한다. Core 상태/manifest/export는 Linux에서도 검증하고 실제 API·프레임·권한은 Windows 장비에서 검증한다. WPF/.NET10·로컬 파일 저장은 검토용 권고안이며 구현되지 않았다. 기본 provider를 호출하지 않는 template 경로와 향후 실제 provider를 명시적으로 분리한다.
