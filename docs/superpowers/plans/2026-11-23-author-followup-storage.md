# 작성자 후속 질문 DB 구현과 인계

기준은 PR #75 설계 197e378과 기본 브랜치 8ba7591이다. 사용자는 DB 구현과 문서 갱신을 요청하고 운영 반영을 보류했다.

## 구현 범위

- 010은 업무 이동, 011은 세션 인증 이동 함수다. 새 저장 기반은 012_author_followup.sql이다.
- 후속 판단·질문·답·건너뜀·답 시각을 revision_questions의 5개 칸으로 보관한다. 과거 행은 판단 전 상태로 시작한다.
- 최초 판단에는 원래 답이 있어야 하고 건너뛰지 않은 상태여야 한다. 판단을 마친 뒤에는 판단 시각과 질문을 바꿀 수 없다. 충분한 답으로 판단해 질문이 없는 경우도 다시 묻지 않는다.
- 원래 답은 판단 후에도 수정·건너뛰기가 가능하다. 판단을 현재 원래 답에 영구 종속시키는 CHECK는 두지 않는다.
- 기존 010 질문 정체·팀 이동 트리거와 011 검색 경로를 유지하고 별도 후속 판단 트리거를 추가한다.
- 후속 답은 수정하거나 건너뛰기로 바꿀 수 있다. 답과 건너뜀은 동시에 저장할 수 없고 응답 시각을 동반한다.

## 게시 이력 호환성

FileHistorySchema와 클라이언트 publishedSchema의 v는 1로 유지하고 질문의 followup을 nullable 선택 필드로 추가한다. 이전 JSON과 history=null은 계속 읽으며 기존 게시본 JSON을 재작성하지 않는다. 이번 작업은 게시 이력 생성기에 새 DB 칸을 연결하지 않는다.

기존 Reader 경로는 실시간 질문 정체와 게시 스냅샷을 합친다. 박효민이 실시간 followup을 연결할 때는 snapshot.followup이 없으면 null로 명시해, 게시 전 후속 질문이 이전 게시본으로 노출되지 않도록 해야 한다. 판단 완료 여부도 실시간 상태에서 복사하지 않는다.

## 검증

012 적용 전 합성 질문을 만든 뒤 업그레이드해 기존 데이터와 초기값을 대조한다. 길이·판단 선행·응답 배타성·응답 시각·판단 불변성·원래 답 수정과 건너뛰기를 DB에서 검사한다. 기존 업무 이동 회귀에는 답을 가진 후속 질문을 넣어 원본·이력 보존과 실패 롤백을 검사한다. v1 이전 이력과 새 선택 필드의 서버·클라이언트 읽기 회귀를 추가한다. 빌드와 전체 검증은 GitHub 격리 CI에서 수행한다.

## 박효민 후속 범위

- 답 저장 이후 판단 API·AI·한도, 후속 답 저장 API, 화면과 도움말, 초안·게시 이력 생성 연결.
- AI 호출 후 저장할 때 원래 답이 호출 당시 값과 같은지 행 잠금 또는 조건부 UPDATE로 검사한다. 이미 판단된 행을 덮어쓰지 않는다.
- PR #75 3절의 미응답 집계 제안과 12절의 집계 보류가 상충한다. 후속 질문이 다음 단계의 필수 차단 조건이 되지 않도록 정책을 정리한다.
- 전용 하루 30회와 #89의 AI_WORKSPACE_LIMITS 설정 관계, 서비스 전체 AI_DAILY_LIMIT과 시연 비용을 정리한다.

## 적용 경계

운영 010·011·012와 앱 배포는 보류한다. 이후 운영 적용에는 백업, migration 순서, 앱 역할 권한, 새 버전 검증을 포함한 별도 실행 절차가 필요하다.
