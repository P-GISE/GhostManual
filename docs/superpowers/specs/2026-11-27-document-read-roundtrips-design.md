# 문서함·파일 초기 조회 왕복 축소

사용자가 PR121 병합과 중복 조회/읽기 왕복 축소·회귀·동일 조건 재측정을 지시했다. 기준은 PR121 병합41dd4e7이며 첫 기준선은 f080c1f/45988619065다.

## 선택한 구현
- 전역 TTL 캐시는 소속/로그아웃/화면 변경 뒤 오래된 응답을 재사용할 수 있어 제외한다. 요청 중 Promise만 합치면 늦게 마운트되는 SourceMove 등의 중복은 남는다. 현재 route 수명의 UI metadata provider를 선택해 표시용 이름을 공유하고 경로가 바뀌면 이전 값/응답을 버린다. 서버 권한 판단은 캐시하지 않는다.
- 개별 GET를 무조건 병렬화하는 대신 버전 목록이 이미 읽은 최신 상세를 재사용한다. 기존 revisions GET에 includeLatest=1 opt-in을 추가해 {revisions,latest}를 같은 workspace 잠금/트랜잭션 안에서 반환한다. 기존 배열 응답·개별 상세·업로드/폴링/게시 snapshot은 보존한다.
- Reader는 게시 revision만 보며 latest의 답변과 answeredCount도 기존 frozen history 처리 뒤 계산한다. 원문 documentDetails와 이전 본문은 묶지 않는다. 자료/세션/소속 재확인을 생략하지 않는다.

## 검증과 한계
라우트 변경·늦은 응답·이름 갱신·실패 입력 차단, Owner/Reader·게시 답변 동결·권한 회수, 초기 목록1회/개별상세0회와 기존 버전선택/폴링을 검증한다. 기존 단순/다중 형식·전체 CI도 통과해야 한다. 같은 작은 native3형식·30표본·3.5초 pacing·DB013·단일 desktop으로 재측정한다. 요청 수 감소와 p50/p95 변화는 구분하며 속도 향상을 미리 보장하지 않는다.

운영 배포·migration014/backfill·대표 지정·AI/실메일·공유 서버/로컬 빌드/부하는 하지 않는다. 기존 개인 자료·공유·원본·용량/안전 제한·2초 폴링을 유지한다. route metadata는 인증 근거가 아니며 다른 브라우저의 같은 경로 변경을 실시간 동기화하는 범위가 아니다.

Ruling: 사용자 지정 성능 계획의 Task2를 route UI metadata 공유와 목록/최신상세 opt-in으로 구체화한다. API 통합의 실패는 기존 오류로 표시하며 과거 권한 응답이나 legacy 상세로 조용히 fallback하지 않는다.
