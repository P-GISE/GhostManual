# 대표 권한으로 계정 탈퇴가 차단될 때 이양 안내

사용자 지시: PR116 병합 뒤 계정 탈퇴의 대표 권한 차단을 기존 이양 화면으로 연결한다. 앞선 담당 작업 브리핑과 읽기 검토에서 정한 범위를 구현한다. 운영 배포·migration014·backfill·대표 지정은 포함하지 않는다. 원본 PR117/브랜치는 유지한다.

## 계약

DELETE /api/me의 HTTP409+lead_transfer_required만 특별 안내한다. 개인/다른 팀 세션이어도 본인이 대표인 모든 현재 소속 팀을 표시한다. 기존 GET /api/workspaces의 같은 SQL에서014 marker·team/admin·본인pointer를 검사한 lead boolean을 추가한다. 개인/부관리자/member/013은 false이며 기존 소속 필터/세션 확인을 보존한다. 다른 사용자 ID는 반환하지 않는다.

AccountPage는 기존 workspacesSchema를 로컬 확장해 lead를 필수 검증하고 name이 있는 admin+lead 팀만 표시한다. 공유 Teams.tsx는 PR117과 겹치므로 수정하지 않는다. 링크는 검증된 UUID의 /teams/{id}?tab=members이며 기존 화면이 세션 전환·권한 재확인·명시적 이양을 담당한다. 계정 화면에서 POST 이양/세션 전환을 자동 실행하지 않는다.

대표 차단 시 삭제 확인을 해제한다. 동기 잠금으로 중복 mutation을 막고 GET은 no-store다. 조회 중 오래된 링크를 지우며 실패/401/잘못된 body는 링크 없이 명시적 조회 재시도와 팀 목록 링크를 제공한다. 재시도는 GET만 수행하고 팀이 없어졌거나 이양을 마쳐도 사용자가 삭제를 다시 확인해야 한다. 일반409는 기존 오류 처리한다. 언마운트 뒤 응답은 반영하지 않는다.

## 검증·한계

실제014 격리DB의 ownlead/다른대표/팀원/개인/비회원과014없는013 호환, 역할변경 재조회, 개인 또는 다른팀 선택 상태를 검증한다. UI mock은 중복DELETE/조회실패/구응답/일반409/잘못된링크를, 실제E2E는 삭제차단→팀이양→명시적재확인삭제와팀자료/공유보존을 검사한다. 키보드·모바일·태블릿·PC 검사/캡처를 남긴다. 운영014 적용 없이 공개 기능을 활성화했다고 주장하지 않는다.
