# 회사 양식 기반 매뉴얼 설계 (AI-COMPANY-TEMPLATE 1차)

작성: 2026-11-17 · 박효민 결정 · 박기성 검토 반영(2026-11-17, PR #60 댓글과 PR #61)

박기성이 실제 파일로 엔진을 실행해 검토했고, 서버 기반(migration 008, 원본 저장, 비동기 추출)을 PR #61로 먼저 구현해 운영에 반영했다. 이 문서는 그 구현과 합의한 AI 전송 범위에 맞춰 고친 판이다. 처음 판과 달라진 곳은 13절에 모았다.

## 1. 목적과 배경

중간보고서에서 2단계 1순위로 약속한 기능이다. 지금 매뉴얼은 정해진 10개 항목으로만 만들어져, 회사에 이미 인수인계 양식이 있으면 사람이 다시 옮겨 적어야 한다. 회사 양식을 한 번 등록하면 그 양식의 항목대로 초안을 쓰고, 근거가 없는 항목은 지어내지 않고 담당자에게 묻는다.

시연에서 드러난 결함(AI가 완료 기준을 비워 게시가 막히고 이유를 알 수 없음)도 같은 흐름으로 해결한다.

## 2. 목표 / 비목표 / 반목표

목표
- 담당자가 한글·워드 양식을 등록하면 AI가 항목 목록(이름·작성 안내·형태)을 뽑고, 담당자가 고쳐서 확정한다.
- 매뉴얼을 만들 때 양식을 고르면 그 양식의 항목대로 초안이 나온다.
- 근거가 없는 항목은 비워 두고 "채우지 못한 항목"으로 묻는다. 담당자의 답은 그대로 들어간다.
- 같은 "채우지 못한 항목" 흐름을 기본 10개 항목 매뉴얼에도 적용한다.

비목표 (1차 범위 아님)
- 표 형태 항목 (표는 목록으로 받는다)
- 원본 양식 파일의 칸에 내용을 채워 내려받기 (멘토링 답변 뒤 결정)
- 답변을 AI가 다듬는 버튼
- 양식을 다른 계정과 공유 (팀 문서함 설계에서 다룬다)
- AI 없이 규칙만으로 항목 추출
- 구형 한글(hwp v5) 양식. 엔진이 줄 단위 글만 내주어 1차는 hwpx·docx만 받는다
- 제목 계층과 병합 셀 구조 인식

반목표 (이렇게 되면 실패)
- AI가 근거 없는 항목을 지어내 채움
- 양식을 고치거나 지웠더니 이미 게시된 매뉴얼이 바뀜
- 다른 계정의 양식이나 양식 원본이 보임. 공유 링크로 들어온 후임자가 양식 원본을 받음
- 기존 10개 항목 매뉴얼(저장된 초안·게시본)이 열리지 않거나 내용이 달라짐

## 3. 결정 사항

박효민 결정
1. 양식은 한 번 등록해 모든 업무에 쓴다.
2. 양식을 쓰면 매뉴얼 항목이 양식의 항목으로 완전히 바뀐다. 양식이 없으면 기존 10개 항목을 쓴다.
3. 항목마다 이름, 작성 안내(있을 때), 형태(글·목록)를 뽑는다. 표는 목록으로 받고 칸 이름은 작성 안내에 넣는다.
4. 근거 없는 항목은 비워 두고 묻는다. 답은 그대로 넣고 "해당 없음"을 고를 수 있다.
5. 항목 판단은 AI가 한다. 빈 양식을 올리라고 안내하고, **담당자가 미리보기에서 확인한 후보만 AI로 보낸다**(2026-11-17 박기성 제안 수용. 실측에서 작성된 값이 표 셀과 행 글에 섞여 나와 안내만으로는 막을 수 없었다).

작성자 기본값 (박효민 확인함)
- 양식은 여러 개 저장하고 하나를 기본으로 둔다. 매뉴얼을 만들 때 바꿀 수 있다.
- 상단 메뉴에 "양식"을 추가한다.
- 형식은 hwpx·docx, 5 MiB까지. 원본 파일은 보관하고 계정 저장 용량 한도에 포함한다.
- 매뉴얼은 만들 당시의 항목을 복사해 가진다. 양식을 고치거나 지워도 기존 매뉴얼은 그대로다.
- 기존 매뉴얼에 양식을 적용하려면 "이 양식으로 다시 만들기"로 새 초안을 만든다. 게시본은 새로 게시할 때까지 유지된다.
- AI가 실패하거나 차단된 계정은 항목을 직접 입력한다.
- 양식 읽기 AI는 계정당 하루 5회.
- 후임자 답변은 지금처럼 검수된 게시본만 근거로 한다.

작성자 판단 (설계 중 정함, 확인 필요)
- 기존 10개 항목 매뉴얼의 저장 형태는 바꾸지 않는다. 읽는 쪽에 두 형태를 같은 항목 목록으로 바꿔 주는 함수 하나를 둔다(6절).
- 기본 10개 항목 매뉴얼에서 게시 필수인 목적·업무 순서·완료 기준은 "해당 없음"을 고를 수 없다(현재 게시 규칙 유지).

## 4. 사용 흐름

양식 등록
1. "양식" 메뉴 → "양식 등록" → 파일 선택. 안내: "내용이 채워진 문서가 아니라 빈 양식을 올리세요."
2. 서버가 파일을 받아 두고(202) 워커가 글과 표의 칸을 후보로 꺼낸다. 화면은 2초 간격으로 상태를 다시 읽는다.
3. 후보 확인 화면: 꺼낸 후보가 모두 체크된 채로 나온다. 경고 "작성된 값이 섞여 있을 수 있습니다"를 보이고, 담당자가 AI로 보내면 안 되는 줄의 체크를 푼다.
4. "AI로 항목 정리"를 누르면 체크한 후보만 AI로 가고, AI가 항목 목록(이름·작성 안내·형태)으로 정리한다. 이 버튼을 누르기 전에는 AI 요청을 만들지 않는다.
5. 항목 확인 화면에서 항목 이름·작성 안내·형태를 고치고, 순서를 바꾸고, 지우거나 추가한 뒤 "확정"한다. 확정 전 양식은 매뉴얼에 쓸 수 없다.
6. AI를 쓸 수 없거나(비활성, 관리자 차단, 한도 초과) 추출이 실패했거나 후보가 없으면 3·4를 건너뛰고 5에서 항목을 직접 입력한다.
7. 목록에서 기본 양식을 지정한다. 첫 확정 양식은 자동으로 기본이 된다.

매뉴얼 만들기
1. 업무 화면의 "매뉴얼 만들기"에 양식 선택이 생긴다. 기본 양식이 선택돼 있고 "기본 항목(양식 없음)"으로 바꿀 수 있다. 확정된 양식이 없으면 선택란을 보이지 않는다.
2. AI가 항목마다 답변 기록에서 근거를 찾아 쓴다. 근거가 없으면 그 항목을 비운다.
3. 작성 화면 위에 "채우지 못한 항목 N개"가 뜬다. 항목마다 이름과 작성 안내를 보여 주고 [답하기] [해당 없음]을 둔다.
4. 답하면 그 글이 항목 내용이 되고 "담당자 작성"으로 표시된다. 목록 항목은 줄마다 한 항목이다.
5. 빈 항목이 없어야 게시할 수 있다. 게시가 막히면 어떤 항목이 비었는지 이름으로 알려 준다.

## 5. 양식 데이터 (migration 008, PR #61로 구현·운영 반영)

실제 정의는 `db/migrations/008_manual_templates.sql`이다.

- `manual_templates`: `id`, `workspace_id`, `name`(기본값은 파일 이름), `status`, `extraction`(워커가 만든 후보와 경고), `items`(확정 항목), `is_default`, `file_name`, `file_type`(`docx`·`hwpx`), `content`(원본 바이트, 5 MiB까지), `file_bytes`(자동 계산), `created_at`.
- `manual_template_jobs`: 비동기 추출 작업. 양식을 지우면 함께 지워진다.
- DB가 강제하는 것: 문서함당 기본 양식 하나, 기본은 `ready`인 양식만, `items`는 30개까지, `ready`면 항목이 1개 이상.
- 저장 용량: `workspace_file_bytes()`가 업무 원본과 양식 원본을 합산한다. 업로드 한도, 프로필, 관리자 집계가 같은 값을 쓴다.
- 문서함당 양식 20개까지(API에서 검사).
- 상태: `reading`(추출 중) → `review`(후보 준비, 담당자 확인 대기) → `ready`(확정). 추출 실패는 `failed`.

워커가 만드는 `extraction`

```json
{
  "warnings": ["항목명 후보를 확인하세요. 작성된 값이 후보에 포함될 수 있습니다."],
  "candidates": [
    { "candidateId": "body/block/1:0", "name": "완료 기준", "guide": "", "kind": "text",
      "sourceRefs": [{ "blockPath": "body/block/1", "cellIndex": 0 }] }
  ]
}
```

- 비어 있지 않은 문단과 표의 칸이 모두 후보가 된다. 최대 200개이고 넘으면 경고가 붙는다. 0개여도 `review`가 될 수 있다.
- `guide`는 빈 문자열, `kind`는 `text`로 온다. 항목 이름·작성 안내·형태의 판단은 AI 정리 단계와 담당자 확인에서 한다.

확정 항목 `items`(API에서 검사): `id`(양식 안에서 고유한 짧은 문자열, 확정 때 부여), `name`(1~80자), `guide`(0~500자), `kind`(`text` 또는 `list`). 1~30개.

## 6. 매뉴얼 데이터

DB 칸은 그대로다(`manuals.draft`, `manual_versions.content`는 jsonb). 초안 형태가 둘이 된다.

- 기본 형태: 지금의 `ManualDraftSchema` 그대로.
- 양식 형태:

```ts
{
  title: string,
  template: { id: string, name: string },   // 만들 당시 값의 복사본
  sections: [{
    id: string, name: string, guide: string, kind: "text" | "list",
    text: string | null,        // kind=text
    items: string[],            // kind=list
    state: "filled" | "empty" | "na",
    by: "ai" | "human"
  }],
  unknowns: string[],
  references: [{ paragraphId, quote, field }]   // field는 section id
}
```

- `sections` 유무로 두 형태를 구분한다. 스키마는 두 형태의 합집합으로 검사한다.
- 읽는 쪽 공통 함수 `toSections(draft)`를 하나 둔다. 기본 형태를 같은 `sections` 목록으로 바꿔 준다(목적·시작 조건·주기·담당 역할·준비 자료·사용 시스템·업무 순서·주의 사항·예외 상황·완료 기준). 매뉴얼 보기, PDF, 후임자 답변의 문단 수집, "채우지 못한 항목" 패널은 이 함수의 결과만 쓴다.
- 쓰는 쪽은 형태별로 저장한다. 기본 형태에서 "답하기"는 해당 칸에 값을 넣는다.
- 게시 규칙: 기본 형태는 현재 규칙 그대로. 양식 형태는 `empty`인 항목이 없고 `filled`인 항목이 하나 이상이며 미확인 항목을 모두 확인해야 한다.
- 게시 거부 응답에 빈 항목 이름 목록을 넣는다(두 형태 모두).

## 7. AI

- 모델과 호출 방식은 기존 초안 생성과 같다(Claude Sonnet 5.5, 출력은 스키마로 검사, 실패 시 재시도 없이 오류).
- 양식 읽기(항목 정리): 입력은 담당자가 체크한 후보의 글과 요청 안에서만 쓰는 번호·순서다. 출력은 항목 목록이고 항목마다 어느 후보에서 나왔는지 번호를 단다. 프롬프트 요지: 제목·번호 줄·표의 머리 칸을 항목으로 보고, 결재란·기관명·날짜·서명란과 작성된 값으로 보이는 후보는 뺀다. 괄호 설명이나 작성 요령은 작성 안내로 넣는다. 받은 후보에 없는 항목을 만들지 않는다.
- 초안 생성: 기존 입력에 항목 목록(이름·작성 안내·형태)을 더한다. 출력은 항목 id별 내용 또는 "근거 없음". 근거 없는 항목은 `empty`로 저장한다. 추측을 금지한다.
- 한도: 양식 읽기는 새 종류로 계정당 하루 5회, 전체 `AI_DAILY_LIMIT`에 포함. 초안 생성은 기존 한도 그대로.
- 관리자가 AI를 차단한 계정, AI 비활성 환경, 한도 초과에서는 양식 읽기를 건너뛰고 `review` 상태에서 항목을 직접 입력한다. 한도는 실제 호출 직전에 센다.
- 양식 읽기에서 AI로 보내는 것: 담당자가 체크한 후보의 글. 보내지 않는 것: 원본 파일, 체크를 푼 후보, 파일 이름과 문서 정보, 문단·표 행 전체 덤프.
- 초안 생성에서 AI로 보내는 것: 확정 항목의 id·이름·작성 안내·형태와 기존 초안 정책이 허용하는 근거. 양식 원본과 후보는 보내지 않는다.
- 개인정보 안내문에 양식 읽기 전송을 추가한다.

## 8. API

| 경로 | 동작 | 상태 |
|---|---|---|
| `POST /api/templates` | 파일 등록(multipart `file`). 202와 `{id, status:"reading"}` | 구현됨(#61) |
| `GET /api/templates/[id]` | `{id, name, status, fileBytes, extraction}`. 확정 API를 만들 때 `items`, `isDefault`, `fileName`을 더한다 | 구현됨(#61), 확장 필요 |
| `DELETE /api/templates/[id]` | 삭제(원본과 작업 포함). 기존 매뉴얼은 영향 없음 | 구현됨(#61) |
| `GET /api/templates` | 내 양식 목록(이름, 상태, 항목 수, 기본 여부) | 박효민 |
| `POST /api/templates/[id]/read` | `{candidateIds}`를 받아 그 후보만 AI로 보내고 항목 초안을 돌려준다. 저장하지 않는다 | 박효민 |
| `PATCH /api/templates/[id]` | 이름, 항목 저장과 확정(`ready`), 기본 지정. `failed`·`review`에서 직접 입력한 항목도 받는다 | 박효민 |
| `POST /api/sources/[id]/generate` | `templateId` 추가. 생략하면 기본 양식, `null`이면 기본 항목 | 박효민 |
| `PATCH /api/manuals/[id]` | 두 형태 모두 받음 | 박효민 |
| `POST /api/manuals/[id]/publish` | 거부 시 빈 항목 이름 포함 | 박효민 |

- 모든 양식 API는 로그인한 소유자만 쓴다. 공유 링크 Reader와 다른 문서함의 접근은 404.
- `read`는 받은 `candidateIds`가 그 양식의 `extraction`에 있는지 확인하고, 없는 번호가 있으면 거부한다.
- 현재 권한 검사(`assertTemplateOwner`와 워커의 작업 검사)는 "세션 사용자가 그 문서함의 주인 계정"을 요구한다. 팀 문서함에는 주인 계정이 없으므로 팀 문서함 구현 때 팀원 검사로 함께 바꾼다([팀 문서함 설계](2026-11-17-team-library-design.md)).

## 9. 화면

- `/templates`: 양식 목록(이름, 항목 수, 상태, 기본 표시), 등록 버튼, 기본 지정, 삭제.
- `/templates/[id]`: 상태에 따라 두 단계. 후보 확인(체크 목록, 경고, 전체 선택·해제, "AI로 항목 정리", "직접 입력")과 항목 확인·수정(항목마다 이름, 작성 안내, 형태. 위아래 이동, 삭제, 추가, 확정). 추출 중에는 진행 표시, 실패하면 이유와 직접 입력·삭제.
- 업무 화면: "매뉴얼 만들기" 옆 양식 선택. 양식 매뉴얼이 있는 업무에는 "이 양식으로 다시 만들기".
- 매뉴얼 작성 화면: "채우지 못한 항목" 패널, 항목별 작성 칸(형태에 맞게 글 또는 줄 단위 목록), 항목 옆 출처 표시(AI 초안·담당자 작성·해당 없음).
- 매뉴얼 보기·PDF·후임자 화면: `toSections` 결과를 순서대로 그린다. "해당 없음" 항목은 이름과 "해당 없음"을 보인다.
- 도움말에 양식 등록 설명을 추가한다.

## 10. 검증

- 단위: `toSections`(기본 형태 10개 항목 순서와 내용 보존), 두 형태 스키마, 게시 규칙, 빈 항목 이름 응답.
- 통합: 양식 API의 계정 격리와 Reader 차단, 양식 삭제 뒤 기존 매뉴얼·게시본 불변, 저장 용량 합산, AI 한도.
- E2E(AI는 고정 응답): 등록 → 항목 수정·확정 → 양식으로 초안 → 빈 항목 답하기·해당 없음 → 게시 → 후임자 보기. 기존 10개 항목 매뉴얼의 기존 E2E가 그대로 통과.
- 접근성: 새 화면 두 개와 패널.
- 품질 측정(최종보고서용): 합성 양식 3종(표 서식 인계·인수서, 긴 문서형 편람, 민간형)과 합성 업무 3건으로 9회. 항목 추출 정확도(사람이 고친 항목 수), 근거 있는 항목을 채운 비율, 근거 없이 채운 항목 수(목표 0).

## 12. 정하지 못한 것

- 결과물을 원본 양식 파일로 내보낼지, 표 항목이 필요한지: [멘토링 질문](../../qa/2026-11-16/mentoring-questions.md) 답변 뒤 2차로 정한다.
- 팀 문서함이 생기면 양식의 소유를 팀으로 옮기는 방법: 팀 문서함 설계에서 다룬다.
- 큰 양식: 실제 한글 보고 양식 하나에서 문단 205개와 표 행 413개가 나왔다. 후보는 200개에서 잘리므로 뒤쪽 항목이 보이지 않는다. 잘린 경우 직접 추가로 보완하고, 후보 수를 줄이는 방법(빈 칸·중복 제거, 페이지 나눔)은 측정 뒤 정한다.
- 구형 한글(hwp v5) 지원 여부: 줄 단위 글만으로 후보를 만들지는 2차로 정한다.
