# 회사 양식 기반 매뉴얼 설계 (AI-COMPANY-TEMPLATE 1차)

작성: 2026-11-17 · 박효민 결정 · 박기성 검토 필요(migration 008, 양식 파일 저장, 추출 호출 방식)

## 1. 목적과 배경

중간보고서에서 2단계 1순위로 약속한 기능이다. 지금 매뉴얼은 정해진 10개 항목으로만 만들어져, 회사에 이미 인수인계 양식이 있으면 사람이 다시 옮겨 적어야 한다. 회사 양식을 한 번 등록하면 그 양식의 항목대로 초안을 쓰고, 근거가 없는 항목은 지어내지 않고 담당자에게 묻는다.

시연에서 드러난 결함(AI가 완료 기준을 비워 게시가 막히고 이유를 알 수 없음)도 같은 흐름으로 해결한다.

## 2. 목표 / 비목표 / 반목표

목표
- 담당자가 한글·워드 양식을 등록하면 AI가 항목 목록(이름·작성 안내·형태)을 뽑고, 담당자가 고쳐서 확정한다.
- 매뉴얼을 만들 때 양식을 고르면 그 양식의 항목대로 초안이 나온다.
- 근거가 없는 항목은 비워 두고 "채우지 못한 항목"으로 묻는다. 담당자의 답은 그대로 들어간다.
- 같은 "채우지 못한 항목" 흐름을 기본 10개 항목 매뉴얼에도 적용한다.

비목표 (1차 범위 아님)
- 표 형태 항목 (표는 목록으로 받는다)
- 원본 양식 파일의 칸에 내용을 채워 내려받기 (멘토링 답변 뒤 결정)
- 답변을 AI가 다듬는 버튼
- 양식을 다른 계정과 공유 (팀 문서함 설계에서 다룬다)
- AI 없이 규칙만으로 항목 추출

반목표 (이렇게 되면 실패)
- AI가 근거 없는 항목을 지어내 채움
- 양식을 고치거나 지웠더니 이미 게시된 매뉴얼이 바뀜
- 다른 계정의 양식이나 양식 원본이 보임. 공유 링크로 들어온 후임자가 양식 원본을 받음
- 기존 10개 항목 매뉴얼(저장된 초안·게시본)이 열리지 않거나 내용이 달라짐

## 3. 결정 사항

박효민 결정
1. 양식은 한 번 등록해 모든 업무에 쓴다.
2. 양식을 쓰면 매뉴얼 항목이 양식의 항목으로 완전히 바뀐다. 양식이 없으면 기존 10개 항목을 쓴다.
3. 항목마다 이름, 작성 안내(있을 때), 형태(글·목록)를 뽑는다. 표는 목록으로 받고 칸 이름은 작성 안내에 넣는다.
4. 근거 없는 항목은 비워 두고 묻는다. 답은 그대로 넣고 "해당 없음"을 고를 수 있다.
5. 항목 판단은 AI가 한다. 빈 양식을 올리라고 안내한다.

작성자 기본값 (박효민 확인함)
- 양식은 여러 개 저장하고 하나를 기본으로 둔다. 매뉴얼을 만들 때 바꿀 수 있다.
- 상단 메뉴에 "양식"을 추가한다.
- 형식은 hwp·hwpx·docx, 5 MiB까지. 원본 파일은 보관하고 계정 저장 용량 한도에 포함한다.
- 매뉴얼은 만들 당시의 항목을 복사해 가진다. 양식을 고치거나 지워도 기존 매뉴얼은 그대로다.
- 기존 매뉴얼에 양식을 적용하려면 "이 양식으로 다시 만들기"로 새 초안을 만든다. 게시본은 새로 게시할 때까지 유지된다.
- AI가 실패하거나 차단된 계정은 항목을 직접 입력한다.
- 양식 읽기 AI는 계정당 하루 5회.
- 후임자 답변은 지금처럼 검수된 게시본만 근거로 한다.

작성자 판단 (설계 중 정함, 확인 필요)
- 기존 10개 항목 매뉴얼의 저장 형태는 바꾸지 않는다. 읽는 쪽에 두 형태를 같은 항목 목록으로 바꿔 주는 함수 하나를 둔다(6절).
- 기본 10개 항목 매뉴얼에서 게시 필수인 목적·업무 순서·완료 기준은 "해당 없음"을 고를 수 없다(현재 게시 규칙 유지).

## 4. 사용 흐름

양식 등록
1. "양식" 메뉴 → "양식 등록" → 파일 선택. 안내: "양식의 글이 AI로 전송됩니다. 내용이 채워진 문서가 아니라 빈 양식을 올리세요."
2. 서버가 기존 문서 추출 엔진으로 글과 표를 꺼내고, AI가 항목 목록을 만든다.
3. 확인 화면에서 항목 이름·작성 안내·형태를 고치고, 순서를 바꾸고, 지우거나 추가한 뒤 "확정"한다. 확정 전 양식은 매뉴얼에 쓸 수 없다.
4. 목록에서 기본 양식을 지정한다. 첫 양식은 자동으로 기본이 된다.

매뉴얼 만들기
1. 업무 화면의 "매뉴얼 만들기"에 양식 선택이 생긴다. 기본 양식이 선택돼 있고 "기본 항목(양식 없음)"으로 바꿀 수 있다. 확정된 양식이 없으면 선택란을 보이지 않는다.
2. AI가 항목마다 답변 기록에서 근거를 찾아 쓴다. 근거가 없으면 그 항목을 비운다.
3. 작성 화면 위에 "채우지 못한 항목 N개"가 뜬다. 항목마다 이름과 작성 안내를 보여 주고 [답하기] [해당 없음]을 둔다.
4. 답하면 그 글이 항목 내용이 되고 "담당자 작성"으로 표시된다. 목록 항목은 줄마다 한 항목이다.
5. 빈 항목이 없어야 게시할 수 있다. 게시가 막히면 어떤 항목이 비었는지 이름으로 알려 준다.

## 5. 양식 데이터 (migration 008, 박기성 검토 필요)

```sql
CREATE TABLE manual_templates(
  id uuid PRIMARY KEY,
  workspace_id uuid NOT NULL REFERENCES workspaces ON DELETE CASCADE,
  name text NOT NULL,                       -- 기본값은 파일 이름
  status text NOT NULL CHECK(status IN ('reading','review','ready','failed')),
  items jsonb NOT NULL DEFAULT '[]',        -- [{id,name,guide,kind}]
  is_default boolean NOT NULL DEFAULT false,
  file_name text NOT NULL,
  file_bytes bigint NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE(workspace_id,id)
);
CREATE UNIQUE INDEX manual_templates_default ON manual_templates(workspace_id) WHERE is_default;
```

- 항목: `id`(양식 안에서 고유한 짧은 문자열), `name`(1~80자), `guide`(0~500자), `kind`(`text` 또는 `list`). 양식 하나에 1~30개.
- 상태: `reading`(추출·AI 중) → `review`(담당자 확인 대기) → `ready`(확정). 실패하면 `failed`이고 직접 입력으로 `review`가 될 수 있다.
- 원본 파일의 저장 위치와 암호화는 기존 문서 원본과 같은 방식을 쓴다. 표의 칸 구성은 박기성이 정한다.
- 계정 저장 용량 합계에 `file_bytes`를 더한다.
- 계정당 양식은 20개까지.

## 6. 매뉴얼 데이터

DB 칸은 그대로다(`manuals.draft`, `manual_versions.content`는 jsonb). 초안 형태가 둘이 된다.

- 기본 형태: 지금의 `ManualDraftSchema` 그대로.
- 양식 형태:

```ts
{
  title: string,
  template: { id: string, name: string },   // 만들 당시 값의 복사본
  sections: [{
    id: string, name: string, guide: string, kind: "text" | "list",
    text: string | null,        // kind=text
    items: string[],            // kind=list
    state: "filled" | "empty" | "na",
    by: "ai" | "human"
  }],
  unknowns: string[],
  references: [{ paragraphId, quote, field }]   // field는 section id
}
```

- `sections` 유무로 두 형태를 구분한다. 스키마는 두 형태의 합집합으로 검사한다.
- 읽는 쪽 공통 함수 `toSections(draft)`를 하나 둔다. 기본 형태를 같은 `sections` 목록으로 바꿔 준다(목적·시작 조건·주기·담당 역할·준비 자료·사용 시스템·업무 순서·주의 사항·예외 상황·완료 기준). 매뉴얼 보기, PDF, 후임자 답변의 문단 수집, "채우지 못한 항목" 패널은 이 함수의 결과만 쓴다.
- 쓰는 쪽은 형태별로 저장한다. 기본 형태에서 "답하기"는 해당 칸에 값을 넣는다.
- 게시 규칙: 기본 형태는 현재 규칙 그대로. 양식 형태는 `empty`인 항목이 없고 `filled`인 항목이 하나 이상이며 미확인 항목을 모두 확인해야 한다.
- 게시 거부 응답에 빈 항목 이름 목록을 넣는다(두 형태 모두).

## 7. AI

- 모델과 호출 방식은 기존 초안 생성과 같다(Claude Sonnet 5.5, 출력은 스키마로 검사, 실패 시 재시도 없이 오류).
- 양식 읽기: 입력은 추출된 양식의 글(앞에서 20,000자까지). 출력은 항목 목록. 프롬프트 요지: 제목·번호 줄·표의 머리 칸을 항목 후보로 보고, 결재란·기관명·날짜·서명란은 뺀다. 괄호 설명이나 작성 요령은 작성 안내로 넣는다. 양식에 없는 항목을 만들지 않는다.
- 초안 생성: 기존 입력에 항목 목록(이름·작성 안내·형태)을 더한다. 출력은 항목 id별 내용 또는 "근거 없음". 근거 없는 항목은 `empty`로 저장한다. 추측을 금지한다.
- 한도: 양식 읽기는 새 종류로 계정당 하루 5회, 전체 `AI_DAILY_LIMIT`에 포함. 초안 생성은 기존 한도 그대로.
- 관리자가 AI를 차단한 계정과 AI 비활성 환경에서는 양식 읽기를 건너뛰고 `review` 상태에서 항목을 직접 입력한다.
- AI로 보내는 것: 양식의 글. 보내지 않는 것: 양식 원본 파일, 셀 값(기존 원칙 유지). 개인정보 안내문에 이 전송을 추가한다.

## 8. API

| 경로 | 동작 |
|---|---|
| `GET /api/templates` | 내 양식 목록 |
| `POST /api/templates` | 파일 등록(multipart). 추출·AI 뒤 `review` 또는 `failed` |
| `GET /api/templates/[id]` | 양식 하나 |
| `PATCH /api/templates/[id]` | 이름, 항목, 확정(`ready`), 기본 지정 |
| `DELETE /api/templates/[id]` | 삭제(원본 파일 포함). 기존 매뉴얼은 영향 없음 |
| `POST /api/sources/[id]/generate` | `templateId` 추가. 생략하면 기본 양식, `null`이면 기본 항목 |
| `PATCH /api/manuals/[id]` | 두 형태 모두 받음 |
| `POST /api/manuals/[id]/publish` | 거부 시 빈 항목 이름 포함 |

- 모든 양식 API는 로그인한 소유자만 쓴다. 공유 링크 Reader 세션은 404.
- 조회는 항상 `workspace_id`로 거른다.
- 추출이 기존 문서처럼 비동기(202)여야 하는지는 박기성이 정한다. 비동기면 `reading` 상태를 화면이 2초 간격으로 다시 읽는다.

## 9. 화면

- `/templates`: 양식 목록(이름, 항목 수, 상태, 기본 표시), 등록 버튼, 기본 지정, 삭제.
- `/templates/[id]`: 항목 확인·수정. 항목마다 이름, 작성 안내, 형태. 위아래 이동, 삭제, 추가, 확정.
- 업무 화면: "매뉴얼 만들기" 옆 양식 선택. 양식 매뉴얼이 있는 업무에는 "이 양식으로 다시 만들기".
- 매뉴얼 작성 화면: "채우지 못한 항목" 패널, 항목별 작성 칸(형태에 맞게 글 또는 줄 단위 목록), 항목 옆 출처 표시(AI 초안·담당자 작성·해당 없음).
- 매뉴얼 보기·PDF·후임자 화면: `toSections` 결과를 순서대로 그린다. "해당 없음" 항목은 이름과 "해당 없음"을 보인다.
- 도움말에 양식 등록 설명을 추가한다.

## 10. 검증

- 단위: `toSections`(기본 형태 10개 항목 순서와 내용 보존), 두 형태 스키마, 게시 규칙, 빈 항목 이름 응답.
- 통합: 양식 API의 계정 격리와 Reader 차단, 양식 삭제 뒤 기존 매뉴얼·게시본 불변, 저장 용량 합산, AI 한도.
- E2E(AI는 고정 응답): 등록 → 항목 수정·확정 → 양식으로 초안 → 빈 항목 답하기·해당 없음 → 게시 → 후임자 보기. 기존 10개 항목 매뉴얼의 기존 E2E가 그대로 통과.
- 접근성: 새 화면 두 개와 패널.
- 품질 측정(최종보고서용): 합성 양식 3종(표 서식 인계·인수서, 긴 문서형 편람, 민간형)과 합성 업무 3건으로 9회. 항목 추출 정확도(사람이 고친 항목 수), 근거 있는 항목을 채운 비율, 근거 없이 채운 항목 수(목표 0).
