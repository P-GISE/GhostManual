# 운영 배포

갱신일: 2026-10-17 (Asia/Seoul). **개발 도구 환경은 구성됨, 제품 실행·배포는 미정**이다.

## 개발 환경과 설정

개발 도구 설치는 Node24·Python3.12·uv·GNU Make·Git을 전제로 한다. 이것은 도구의 요구 조건이며 제품의 기술 선택이 아니다. 설치 명령·버전은 [개발 도구 가이드](개발_도구_가이드.md)와 [versions.mk](../tools/versions.mk)를 따른다.

CodeGraph MCP는 [.codex/config.toml](../.codex/config.toml)에 등록돼 있다. 프로젝트 신뢰와 새 세션 로드가 필요하다. Core 소스가 추가됐으며 기존 앱 인덱스는 재사용하지 않는다. 코드 인덱스 생성 여부는 실제 파일로 확인한다. .dev-tools 캐시는 Git에 포함하지 않는다.

## 현재 CI

[Iron Laws](../.github/workflows/iron-laws.yml)는 PR 변경 파일과 수동 전체 검사를 제공한다. [Strix](../.github/workflows/strix.yml)는 계정·키·예산·Docker를 준비한 뒤 수동 실행한다. 제품 테스트·빌드·배포 workflow는 제거돼 현재 없다.

확인 시점 초기화 commit d13fe60의 GitHub Iron Laws check는 success였다. 이 결과는 제품 테스트·제품 보안·실 LLM 검증을 뜻하지 않는다. 이후 변경에는 새 검증이 필요하다.

## 제품 실행·배포 절차

미정. 요구사항·기술·제공자·대상 환경을 정한 뒤 실행 명령·변수명·배포·migration·health·모니터링·롤백을 작성한다. 과거 앱의 포트·서버·비밀 설정을 새 기본값으로 가져오지 않는다.

## PC 수집 PoC 전제

사용자가 PC 화면·여러 앱의 작업 흐름 수집을 선택했다. 첫 OS는 Windows로 확인됐다. Windows 버전/장비·화면/앱 정보 수집 권한·로컬 보관·외부 전송·생성 모델·비용 상한·보관/삭제를 실험 전에 결정한다. 설치된 Node/Python 도구 버전으로 데스크톱 제품 프레임워크를 확정하지 않는다. OS 권한 거부·잠금·보호된 화면과 앱 접근 한계는 PoC 시나리오에 포함한다.

## PoC 구현 환경 제안

[구현 설계](superpowers/specs/2026-10-16-windows-local-poc-design.md)는 Windows11 x64 단일 모니터·일반 권한, .NET10/C#·WPF를 첫 후보로 제안한다. 공식 release metadata의 SHA512를 검증한 SDK 10.0.402를 이 Linux 작업 환경의 저장소 밖에 설치하고 global.json에 고정했다. NuGet에서 확인한 Microsoft.NET.Test.Sdk18.11.0·xunit2.9.3·xunit.runner.visualstudio4.0.1을 중앙 버전/lock 파일로 고정해 실제 restore/test/build했다. Core unit과 Windows 실제 수집은 별개 검증이다. 실제 OS/앱/Office·허용 범위·보관·provider 전송/비용 조건은 실행 전 확정한다.

## Core 개발·검증 명령

공식 .NET SDK10.0.402를 설치한 환경에서 저장소 루트 기준:

```sh
dotnet restore --locked-mode
dotnet test --no-restore
dotnet build -c Release --no-restore
```

global.json은 해당 SDK에 고정돼 있고 중앙 패키지 버전과 각 packages.lock.json을 추적한다. 현재는 라이브러리와 테스트만 있으며 `dotnet run`으로 시작할 데스크톱 앱은 없다. Core 검증 자동 CI와 Windows 설치/배포는 아직 구성하지 않았다. 이번 Linux 도구 설치 경로는 `/workspace/scratch/ghostmanual-dotnet/sdk/dotnet`이며 저장소에 SDK 바이너리를 포함하지 않는다.

## AWS·Tailscale·Cloudflare 서버 연결 작업

2026-10-17 사용자 지시로 서버 연결과 GhostManual 서브도메인 생성 작업을 시작했다. 서버 접속/DNS 변경은 이번 요청 범위다. 현재는 연결 조건 확인 단계이며 실제 서버·DNS를 변경하지 않았다.

| 항목 | 확인/필요 상태 |
|---|---|
| AWS | 사용자가 us-east-1 콘솔 링크 제공. 인스턴스 ID·실제 리전·OS·공인 IP·접속 계정은 미확인 |
| Tailscale | 대상100.108.2.6의 관리 링크 제공. 이 작업 환경의 VPN 설정은 false, TCP 대상 허용 목록은 비어 있음 |
| 인증 | 환경 상태에 outbound identity·secret·runtime variable 바인딩 없음. 서버 SSH 인증·Cloudflare DNS 편집 권한 미연결 |
| 브라우저 | 현재 호출 가능한 로그인 브라우저 제어 도구 없음. 관리 화면 링크는 인증 수단이 아님 |
| DNS 이름 | 사용자 확인: pigs0516.com. 연결 대상 ghostmanual.pigs0516.com. 레코드 생성/사용 가능 여부 미확인 |
| 제품 실행 대상 | Core 라이브러리·테스트만 존재. 서버용 웹 앱/API·Windows 수집기는 미구현 |

### 연결 조건

1. 지원되는 작업 환경 설정에서 Tailscale VPN과100.108.2.6 대상 TCP 허용을 구성한 뒤 적용 상태를 확인한다. 서버 OS/접속 방법을 확인해 Linux SSH라면22 등 실제 포트를 사용한다. 현재 VPN 미설정 상태에서 우회 경로를 만들거나 관리 콘솔 링크를 SSH 대상으로 쓰지 않는다.
2. 서버 접속 계정과 인증 수단을 안전한 환경 바인딩으로 제공한다. 키·비밀번호를 채팅/Git에 넣지 않는다. SSH 호스트키를 검증한다.
3. Cloudflare 대상 zone의 기본 도메인과 권한을 연결한다. API 방식이면 해당 zone에 한정한 Zone Read/DNS Edit 권한을 사용한다. Tunnel 방식은 별도 해당 권한과 서버 연결이 필요하다.

### 접속 후 실행 순서

1. 서버 OS·실행 사용자·사용 가능한 디스크·리스닝 포트·기존 프록시/서비스를 읽기 전용으로 확인한다. 운영 설정이나 자격증명 원문을 출력하지 않는다.
2. AWS 인스턴스와 Tailscale 장비가 같은 대상인지 확인하고 목적지 서비스·포트를 결정한다. AWS 콘솔의 기본 리전만으로 인스턴스 위치를 추정하지 않는다.
3. Cloudflare zone·기존 DNS·동일 이름 사용 여부·TLS 구성을 조회하고 변경 전 해당 설정을 복구 가능한 형태로 보관한다. 기존 레코드는 임의로 덮어쓰지 않는다.
4. 서비스의 공인 원점 주소 또는 Cloudflare Tunnel 경로를 확인한 뒤 새 서브도메인만 추가한다. 100.108.2.6은 Tailscale 사설 주소이므로 공개 DNS 원점 A 레코드로 직접 사용해 인터넷 서비스가 연결된다고 가정하지 않는다.
5. 선택한 서비스의 health·외부 HTTPS·인증·인증서와 기존 서비스 영향 여부를 확인한다. 실패하면 이번 작업에서 만든 DNS/프록시 변경만 복구한다.
6. 실제 명령·환경·DNS 결과·복구 정보를10과99에 기록한다. 서버 연결/서브도메인 생성만으로 Windows 화면 수집이나 PoC 성공을 선언하지 않는다.

관리 콘솔 접근과 네트워크/인증이 마련되면 위 점검부터 재개한다. 신규 유료 인스턴스·Windows/Office 라이선스·도메인 구매는 현재 요청에서 필요성이 확인되지 않아 생성하지 않았다.

### 운영 클라이언트 설치 후 상태

AWS CLI1.46.1·공식 Cloudflare SDK5.9.0을 별도 venv에 설치했고 `make -f tools/Makefile infra-doctor`로 실행/import를 검증했다. OpenSSH는 기존 클라이언트를 사용한다. 재설치는 개발 도구 가이드의 infra-install 명령을 따른다. AWS 읽기 전용 describe-instances는 자격증명 없음으로 실패했고 Cloudflare SDK의 zone 조회는 인증 미설정으로 요청 전에 중단됐다. 앞선 직접 API 접근은 CONNECT403으로 차단됐다. 아직 서버/DNS/TLS 변경은 없다. 기본 도메인은 이제 확인됐으므로 남은 차단은 인증·네트워크·서버 OS/계정·목적지 서비스 확인이다.
