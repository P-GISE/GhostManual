# GhostManual PoC 검증 계획 초안

작성일: 2026-10-16. 상태: 실험 설계 제안. PoC 코드·실험·결과는 아직 없다.

## 목적과 검증 순서

‘자동 수집할 수 있는가’, ‘그 자료로 쓸 만한 매뉴얼을 만들 수 있는가’, ‘문서를 만드는 부담이 줄어드는가’를 순서대로 확인한다. 범용 제품이나 운영 배포를 PoC 완료 조건으로 삼지 않는다.

[제품 기획서](01_제품_기획서.md)의 F-01~07과 연결하며 사용자가 선택한 PC 화면·여러 앱 수집을 대상으로 하며 첫 지원 OS 선택 후 실험 어댑터와 지원 동작을 확정한다.

## 실험 전 결정할 항목

- 첫 지원 OS1개, PC 화면 수집 방식1개, 대표 업무1종, 지원 동작·지원하지 않는 영역
- 합성 데이터로 만든 테스트 업무·정답 절차·필수 단계/분기
- 수집 허용 범위·업로드 전 필터·보관/삭제·외부 모델 전송 여부
- 실제 모델 비교가 필요하면 사용할 계정·모델·비용 상한
- 측정 항목·목표값·업무별 난이도를 실험 전에 기록

초기에는 실제 회사 자료·개인 계정 대신 격리한 합성 업무를 사용한다. 여기서 수집 안전성이 입증돼도 실제 조직 도입 승인을 대신하지 않는다.

## 실험 구성 — 제안

### P0. PC 수집 경로 비교

동일한 합성 업무를 두 앱 이상에서 수행한다. 변화 시점 스크린샷+전면 창/행동 이벤트와 연속 영상+후처리를 비교해 단계 구분·권한·처리량·비용을 기록한다. 첫 후보는 변화 시점 방식이나 성능을 확인한 선택은 아니다. 알림·보호된 창·앱 전환·권한 거부·잠금 화면·모니터 변경은 지원/미지원과 공백 표시를 확인한다. 첫 PoC에서 모든 OS·모든 앱·다중 모니터를 지원한다고 약속하지 않는다.

화면/메타데이터가 수집되는 로컬 경계와 외부 전송 경계를 분리하고 제외/마스킹 후 업로드 입력을 검사한다. 시스템 권한을 얻었다는 사실만으로 업무 데이터 수집·외부 전송에 대한 승인이 있다고 간주하지 않는다.

### P1. 수집 적합성

고정된 지원 동작 목록을 정답 이벤트 로그와 비교한다. 정상 수행·일시정지·범위 이탈·권한 거부·중복 전송·연결 중단을 각각 실행한다.

산출물: 지원 동작별 수집 성공/실패, 순서, 중복, 유실·공백 표시, 제외 정책의 업로드 입력 검사. 수집할 수 없는 의미는 화면 추론으로 관찰 사실처럼 복원하지 않는다.

### P2. 매뉴얼 품질

동일 업무를 최소 5회 기록한 독립 세션에서 초안을 생성하고, 사전에 정한 필수 단계·성공 결과·근거와 비교한다. 이 표본은 초기 feasibility 확인용이며 사용자 전체 효과의 통계적 입증이 아니다.

산출물: 초안, 근거 연결, 누락 단계, 근거 없는 서술, 작성자 보완 시간, 처리 시간·사용량·비용. 모델 실패는 성공한 세션만 남기지 말고 전체 시도에 포함한다.

### P3. 인수인계 가치

가능하면 작성자 아닌 참여자 3명이 각자 매뉴얼을 보고 업무를 수행한다. 비교용 수동 작성 문서도 준비하고 동등한 업무 변형·순서 교차로 학습 영향을 줄인다. 참여자를 구할 수 없으면 시연 수준 결과로 표시하고 가치 검증을 완료로 쓰지 않는다.

산출물: 완료율, 소요 시간, 도움 요청 수, 막힌 단계. 자동 수집+초안 보완과 수동 작성의 전체 문서화 시간을 비교한다. 기록된 업무 수행 자체의 시간과 추가 문서화 시간을 따로 측정한다.

## 잠정 성공·중단 기준

다음은 제안 목표이며 대표 업무를 정한 뒤 실험 시작 전에 확정한다. 측정 후 유리하게 바꾸지 않는다.

| 항목 | 측정 방식 | 잠정 기준 |
|---|---|---|
| 지원 동작 수집 | 올바른 순서로 매칭된 정답 이벤트 / 정답 지원 이벤트 | 95% 이상 |
| 필수 절차 포함 | 초안의 올바른 필수 단계 / 정답 필수 단계 | 90% 이상 |
| 근거 없는 필수 단계 | 실제 기록·작성자 보완으로 지지되지 않는 필수 단계 | 관찰 사례0건 |
| 수집 경계 | 정지·범위 밖·합성 비밀값이 업로드 입력에 포함되는지 | 관찰 사례0건, 발생 시 수집 실험 중단·원인 수정 |
| 인수인계 재현 | 도움 없이 목표 결과 완료 / 전체 참여자 | 초기3명 모두 완료를 목표, 실패는 단계별 분석 |
| 문서화 부담 | 같은 난이도 업무의 추가 문서화 시간 비교 | 중앙값30% 이상 감소 목표 |
| 처리 비용·시간 | 모든 생성 시도의 사용량·오류·경과 시간 | 업무/모델 선택 후 상한 확정, 미정이면 실험 시작하지 않음 |

0건이라는 관찰 결과는 모든 입력에서 유출·환각이 불가능하다는 보증이 아니다.

## 결과 기록과 의사결정

각 실행에 업무/시나리오 ID·수집 방식/버전·세션 ID·기대 결과·실제 결과·근거·오류·시간/비용을 남긴다. 결과가 없는 현재는 모든 항목 ‘미실행’이다.

- Go: 수집 경계를 만족하고 목표 단계·재현성·시간/비용을 만족하면 해당 업무 범위의 MVP 설계 진행.
- Iterate: 수집은 되나 문서 품질이 낮으면 대상 동작·근거·확인 질문을 보완하고 동일 기준으로 재실험.
- Pivot/Stop: 필요한 정보를 관찰할 수 없거나 수집 경계·문서화 부담 목표를 만족하기 어렵다면 수집 방식/제품 범위를 바꾼다. Go로 간주하지 않는다.

제품 코드·DB migration·로그인·운영 배포의 구현 계획은 이 결과와 사용자 검토 후 별도로 작성한다.
