# Pre-Mortem: Windows 업무 수집 PoC

PM Skills pre-mortem 지침 적용. ‘가상의 14일 뒤 PoC가 실패했다’고 놓고 원인을 검토한다. 실제 출시 일정이나 이미 발생한 장애가 아니다. 기준은 [제품 기획서](01_제품_기획서.md)와 [로컬 수집 설계](../superpowers/specs/2026-10-16-windows-local-poc-design.md)다.

## Tigers — 실제 대응이 필요한 위험 가설

| 위험 | 단계 | 대응·담당 | 결정 시점 |
|---|---|---|---|
| 앱 전환만 수집해 실제 필터/집계 단계를 복원하지 못함 | PoC 결과 판정 전 차단 | 제품/평가 담당: 관찰 근거·확인 질문·후임자 재현으로 검증. 단순 outline은 가치 성공 아님 | S-01 평가 전 |
| 원본 화면·무관 앱이 저장/외부 전송됨 | 첫 화면 실험 전 차단 | 수집/QA 담당: raw 메모리 전용·수집 경계·검토/마스크·파일/픽셀 검사 | Task3 완료 전 |
| Windows 장비·Office·권한이 없어 실제 수집을 못 함 | Windows 실험 차단 | 환경 담당: OS/앱/권한 지원표와 실행 장비 확보. Core만 통과한 결과와 분리 | Task2 실제 검증 전 |
| 정답 자료가 수집/모델 입력에 섞여 품질 과대평가 | 품질 평가 차단 | 평가 담당: fixtures/evaluation 분리·정답 접근/오염 여부 기록 | P2/P3 시작 전 |
| 저장 실패·제외 근거가 export에 남음 | 내보내기 완료 차단 | Core/QA 담당: 실패 주입·manifest 유효성·원자적 완료 표시 | Task4 완료 전 |

담당은 역할 제안이며 실제 팀원이 배정된 것은 아니다. 날짜를 임의 확정하지 않고 각 선행 단계 전까지 해결 또는 중단 결정을 남긴다.

## Paper Tigers — 현재 PoC에서 과도하게 키우지 않을 범위

macOS/Linux 동시 지원, 기업용 다중 조직·결제·클라우드 동기화·자동 업무 실행이 없다는 점은 현재 단일 Windows 업무의 수집 가능성 검증을 막지 않는다. 이를 지원한다고 약속하지 않고 운영 제품 요구가 생기면 별도 평가한다.

## Elephants — 말하지 않으면 놓치기 쉬운 가정

- 사용자가 기록을 켜고 매번 근거를 검토할 만큼 가치가 있는가? 추가 작업 시간이 절약 시간을 상쇄할 수 있다.
- 익숙한 수행자는 문서 누락을 알아채지 못한다. 새로운 사람이 실제로 재현해야 한다.
- 캡처 후보가 유효해도 업무의 이유·예외·암묵지를 관찰하지 못할 수 있다. 작성자 설명 비용을 측정한다.
- 합성 과제 성공은 실제 기업의 다양한 앱·정책·민감정보 도입 가능성을 입증하지 않는다.
- template baseline과 실제 모델 생성, 좋은 업무 결과와 좋은 매뉴얼은 다른 성공 지표다.

확인 방법: [인수 시나리오 TC-01~06](04_Windows_PoC_인수_시나리오.md)와 PoC의 문서화 시간·재현 성공·오류/비용 전체 시도 지표로 판단한다. 아직 검증 결과는 없다.
