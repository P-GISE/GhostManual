# GhostManual 제품 기획서 초안

작성일: 2026-10-16. 상태: 핵심 목적 확인, PC 화면·여러 앱 수집 방향 확인, 첫 OS는 Windows, 세부 범위는 검토 중. 구현 승인서나 확정 기술 명세가 아니다.

## 1. 확인된 요구와 가설

**사용자 확인:** 업무 수행 과정을 자동 수집해 인수인계 매뉴얼을 만드는 서비스. 기존 구현을 복원하지 않고 기획·PoC·ERD부터 새로 설계한다. 첫 PoC는 PC 전체 업무에서 화면과 여러 앱의 작업 흐름을 수집한다.

**제품 가설:** 업무를 수행한 직후 수집된 흐름을 검토하는 편이, 기억에 의존해 처음부터 매뉴얼을 쓰는 것보다 빠르고 정확하다. 실제 작성 시간·절차 누락·후임자의 재현 성공으로 검증한다.

## 2. 대상 사용자와 문제 — 제안

| 사용자 | 해결하려는 문제 | 필요한 결과 |
|---|---|---|
| 업무 수행자 | 일을 마친 뒤 화면과 판단을 기억해 문서화하는 부담 | 수행 흐름이 있는 수정 가능한 초안 |
| 업무 검토자 | 자동 생성 내용이 실제 절차·조직 규칙과 맞는지 확인 | 수집 근거·수정·검수 상태 |
| 인수인계 받는 사람 | 문서만 보고 같은 업무를 수행하기 어려움 | 시작 조건·순서·확인 기준·예외와 미확인 사항 |

PoC에서는 수행자와 검토자를 같은 사람이 맡을 수 있다. 기업 조직·부서·복잡한 승인 체계는 아직 요구되지 않았다.

## 3. 핵심 가치와 경계 — 제안

업무 한 건을 기록한 세션에서 수행 순서를 추출하고, 사람이 보완·검수한 뒤 따라 할 수 있는 매뉴얼을 만든다. 사용자 활동을 수집하는 기능과 문서가 업무적으로 옳다는 판단은 분리한다.

자동 수집만으로 업무 목적·선행 조건·암묵적 판단을 모두 알 수 있다고 가정하지 않는다. 관찰할 수 없는 내용은 작성자 확인 질문으로 남긴다. ‘관찰된 동작’, ‘작성자가 추가한 설명’, ‘확인 필요’를 구분한다.

## 4. 수집 방식 결정과 검토

| 방식 | 적합한 업무 | PoC에서 확인할 점 | 한계 |
|---|---|---|---|
| 브라우저 확장 | 웹 서비스 내 반복 업무 | 페이지·행동 순서와 선택적 화면 근거 수집 | 데스크톱 앱·일부 브라우저 영역 접근 불가 |
| PC 화면·여러 앱 | 앱을 오가는 업무 | 권한·화면 기록·업무 구간 구분 | 민감정보 제거·영상 처리·설치 부담 큼 |
| SaaS/API 이벤트 | 지원하는 업무 도구 | 업무 이벤트 의미와 작업 결과 연결 | 도구별 연동·토큰·이벤트 공백 |

**사용자 결정:** PC 화면·여러 앱을 오가는 업무로 PoC를 진행한다. 브라우저 확장이나 SaaS 연동을 첫 구현으로 선택하지 않는다. 첫 OS는 Windows로 확인됐다. macOS/Linux 동시 지원은 이번 PoC에서 약속하지 않는다.

**PC 수집 제안:** 사용자 시작/종료 세션에서 전면 앱·창 전환, 관찰 가능한 행동, 선택한 화면 근거를 시간순으로 묶는다. 연속 영상 중심과 변화 시점 스크린샷+이벤트 중심을 비교하되 첫 후보는 후자로 둔다. 클릭·앱 정보 접근 가능성은 OS별로 다르고 모든 앱의 UI를 구조적으로 읽을 수 있다고 가정하지 않는다. 키 입력 전체·클립보드·파일 전체 내용은 기본 수집 대상에 넣지 않는다.

## 5. 첫 PoC 범위 — 제안

포함: 업무명/목표 입력 → 명시적으로 기록 시작 → 허용 범위 안의 수행 흐름 수집 → 일시정지·재개·종료 → 수집 내용 확인·제외 → 매뉴얼 초안 → 작성자 보완·검수 → 다른 사람의 업무 재현.

초안 필드: 업무 목적, 시작 조건, 준비 사항, 단계별 행동, 예상 결과, 완료 확인, 예외/확인 질문, 수집 근거. 한 번 관찰한 경로를 유일한 정답이나 모든 예외를 다룬 문서로 표시하지 않는다.

첫 검증 제외 제안: 상시 백그라운드 감시, 키 입력 전체 기록, 원격 자동 업무 실행, 조직 전체 활동 분석, 모든 업무 도구 동시 지원, 결제·복잡한 조직 관리, 매뉴얼 질의응답. 필요성이 확인되면 별도 범위로 검토한다.

## 6. 수집 제어와 데이터 원칙 — 제안

- 수집 중임을 표시하고 사용자가 범위·시작·일시정지·종료를 제어한다.
- 비밀번호·쿠키·인증 토큰·업무와 무관한 영역은 수집 대상에서 제외한다. 캡처 화면이 포함되면 업로드 전 제외/마스킹 경로를 PoC로 검증한다.
- 원본 화면·영상·문자 전체를 기본 수집한다고 가정하지 않는다. 대상 업무에 필요한 최소 근거부터 정한다.
- 정지·권한 거부·앱 변경·네트워크 실패가 있으면 기록 공백을 표시한다. 공백을 AI가 수행 사실처럼 채우지 않는다.
- 데이터 보관 기간·삭제 범위·업무 데이터 외부 전송·AI 제공자는 미정이며 실제 수집 실험 전에 정한다.

## 7. 핵심 시나리오와 인수 기준 — 제안

| ID | 시나리오 | 확인할 결과 |
|---|---|---|
| F-01 | 업무 기록 준비·시작 | 업무명·목적·대상 범위와 수집 상태 확인 |
| F-02 | 수행 흐름 수집 | 지원 동작의 순서·출처 보존, 기록 공백 표시 |
| F-03 | 일시정지·종료 | 정지 구간·범위 밖 정보가 업로드에 섞이지 않음 |
| F-04 | 수집 내용 검토 | 불필요/민감 근거 제외 후 생성 입력에서도 제외 |
| F-05 | 초안 생성 | 핵심 단계와 근거 연결, 미관찰 판단은 확인 질문 |
| F-06 | 보완·검수 | 수정 이력·근거 유무·미확인 상태를 구분 |
| F-07 | 인수인계 검증 | 작성자가 아닌 사람이 매뉴얼로 업무 수행, 실패 지점 기록 |

## 8. 진행 판단

[PoC 계획](02_PoC_검증_계획.md)의 실험 결과로 핵심 가치가 확인된 후 제품 MVP 범위를 확정한다. UI·DB·API·배포 구현을 먼저 늘리지 않는다.

미결정: Windows 버전/장비, 실제 앱 조합, 실제 사용자/사용 환경, 허용 데이터, 보관 기간, 모델/예산, 목표 일정. 개념 ERD는 [03 데이터베이스 설계](../03_데이터베이스_설계.md)의 제안이며 물리 schema는 아직 없다.

## 9. 첫 Windows 대표 업무

사용자 최신 선택은 웹에서 자료 조회 → Excel 정리 → 결과 문서 작성이다. 구체적인 [S-01 시나리오](03_Windows_대표업무_시나리오.md)에는 평가용 합성 구매 요청12건, 기간/상태 조건, 부서별 집계, 보고서 내용과 실패 변형을 제안했다. 실제 회사 자료를 요구하지 않는다. 정답/평가 자료는 수집 세션·모델 입력에서 분리한다.

파일 탐색기→문서→메일 초안은 먼저 응답된 후보로 남기며 첫 PoC에 동시에 추가하지 않는다. 최신 선택을 기준으로 범위를 좁혔다.
