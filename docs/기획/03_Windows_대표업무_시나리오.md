# Windows 대표 업무 PoC 시나리오 — S-01

상태: 실행 준비용 제안. 사용자 확인은 **Windows / 웹 자료 조회 → Excel 정리 → 결과 문서 작성**이다. Windows 수집기·모델·PoC 실행 결과는 아직 없다.

## 1. 선택과 범위

같은 질문에 ‘파일 탐색기 → 문서 편집 → 메일 초안’ 응답 뒤 ‘웹 → Excel → 결과 문서’ 응답이 추가돼 최신 답변을 첫 시나리오로 반영했다. 전자는 확장 후보이며 첫 시나리오에 메일 발송·파일 검색을 함께 넣지 않는다.

세부 소재는 합성 구매 요청을 기간·상태로 걸러 부서별 집계 보고서를 만드는 것으로 제안한다. 사용자의 실제 회사 업무가 구매라는 뜻은 아니다.

도구 조합 제안: Windows의 Edge/Chrome 중 하나, Excel, 문서 편집기(Word 후보). 정확한 OS/앱 버전·라이선스·장비·수집 프레임워크는 실험 전에 확인한다. 동등한 결과를 만드는 Excel 집계 방법은 허용하고 특정 UI 클릭 경로를 정답으로 고정하지 않는다.

## 2. 입력 자료와 과제

- [합성 웹 페이지](fixtures/purchase-requests.html): 요청12건과 과제, CSV 다운로드. 외부 회사 사이트에 접속하지 않는다.
- [원자료 CSV](fixtures/purchase-requests.csv): 날짜·부서·상태·원화 금액. UTF-8 BOM 인코딩이다. 필요한 경우 Excel에서 UTF-8로 가져온다.
- 평가자 전용: [정답 집계](evaluation/expected-summary.csv), [정답 보고서 내용](evaluation/expected-report.md).

과제: 요청일 2026-10-05~2026-10-09(양끝 포함), 상태 ‘승인’ 조건으로 부서별 승인 건수·금액과 전체 합계를 Excel로 정리하고 결과 문서를 작성한다. 금액은 거래 총액이며 세금·환율 계산은 하지 않는다.

원자료12건 중 대상7건, 합계960,000원이다. 부서별 결과는 영업팀2건210,000원·운영팀3건250,000원·개발팀2건500,000원이다. 이 문서와 정답 파일은 평가자 자료이며 기록 대상 창·생성 입력에서 제외한다. 입력 웹 페이지에는 계산된 정답을 넣지 않는다. 정답은 정적 서버 제공 폴더 fixtures 밖의 evaluation에 둔다. 참여자에게는 원자료 페이지와 CSV만 제공한다.

## 3. 정답 절차와 기대 근거

| 단계 | 사용자 행동 | 기대 결과 | 수집/검토할 근거 |
|---|---|---|---|
| S1 | 업무 목적·기간·상태 조건 확인 후 기록 시작 | 대상 업무와 허용 앱이 정해짐 | 수집 상태·과제 화면·허용 범위 |
| S2 | 웹 원자료 확인·CSV 다운로드 | 출처·조회 조건·다운로드가 식별됨 | 브라우저 자료 화면·파일 받기 전후 변화 |
| S3 | Excel에서 CSV를 열거나 가져오기 | ID·날짜·부서·상태·금액12건의 열 구분이 맞음 | 브라우저→Excel 전환·열/자료 개수 확인 |
| S4 | 기간 양끝·승인 상태 적용 | 대상7건만 집계에 포함됨 | 조건 설정·필터된 자료·누락/제외 구분 |
| S5 | 부서별 건수·금액 및 합계 계산 | 부서3개와 전체7건960,000원 | 집계 과정·최종 값·완료 확인 |
| S6 | 문서 편집기로 결과 작성·저장 | 제목·조건·집계·합계·합성 자료 표시 | Excel→편집기 전환·보고서 결과·저장 |
| S7 | 기록 종료·근거 확인·민감/무관 내용 제외 | 종료 상태와 생성할 입력 집합 확인 | 세션 끝·gap·제외/마스크 적용 |

단계는 의미 단위다. 마우스 클릭·스크롤 횟수가 달라도 같은 결과면 오답으로 보지 않는다. 매뉴얼에는 재현에 필요한 필터 조건·자료 가져오기·집계·결과 확인이 포함돼야 한다. 관찰할 수 없었던 판단·수식·경로는 작성자 확인 질문으로 남긴다.

## 4. 실행 준비

웹 자료는 같은 폴더의 CSV 링크를 이용한다. 단순 로컬 페이지로 열거나 필요 시 저장소 루트에서 아래처럼 loopback 정적 서버로 제공한다. 이것은 테스트 자료 제공이며 GhostManual 제품 서버가 아니다.

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory docs/기획/fixtures
```

Windows 환경에서는 설치된 Python 명령을 확인해 동일 인자를 사용한다. 자료 페이지 주소는 `http://127.0.0.1:8765/purchase-requests.html`이다. 실제 앱·장비 검증을 했다는 뜻은 아니다. 정답 CSV/보고서는 평가자만 열고 수집 대상에 넣지 않는다.

실험 전 수집 범위·로컬 임시 보관·마스킹·외부 전송·삭제·모델·비용/시간 상한을 정한다. 계정·자격증명·회사 원문은 사용하지 않는다.

## 5. 성공 조건과 평가

| 구분 | 확인 기준 |
|---|---|
| 업무 결과 | 조건에 맞는 요청 ID7개, 부서별 건수·금액·총합이 정답과 일치 |
| 보고서 | 기간/상태·부서별 결과·전체 합계·합성 자료 표시 포함 |
| 절차 재현 | 작성자 아닌 사람이 생성·검수 매뉴얼만 보고 동일 과제를 수행. 정답 파일은 보여주지 않음 |
| 출처 | 웹·Excel·편집기 전환과 핵심 단계의 관찰 근거/작성자 보완을 구분 |
| 수집 경계 | 일시정지·무관 앱·합성 비밀 문자열이 업로드/모델 입력/내보내기에 포함되는지 검사 |
| 측정 | 전체 시도의 누락·오류·시간·비용·문서 보완·도움 요청 기록 |

기본 기능·안전성·비용 판단은 [PoC 계획](02_PoC_검증_계획.md)을 따른다. 목표 수치는 제안이며 실험 전 확정한다. 성공한 결과 문서만으로 매뉴얼 생성 품질을 입증하지 않는다.

## 6. 오류·경계 변형

- 날짜 바깥 REQ-008/009와 대기/반려 REQ-003/010/011이 잘못 포함되는지 확인한다.
- CSV의 한글·날짜·금액 형식이 잘못 열리는 경우 도움 요청과 복구 절차를 기록한다.
- Excel 집계 전후 수집을 중지해 공백이 추측한 단계로 바뀌지 않는지 확인한다.
- 편집기 미설치·권한 상실·화면 잠금·앱 재시작은 지원 불가/중단으로 기록한다.
- 보고서 편집 또는 저장 근거가 없으면 문서 저장 성공을 추론하지 않는다.

## 7. 결과 기록 양식

실행 ID / 대상 OS·앱·수집기·모델 버전 / 시나리오·자료 버전 / 시도 번호 / 지원 동작 목록 / 정답 매칭·공백 / 제외 검사 / 업무 결과 / 매뉴얼 품질 / 시간·비용 / 도움 요청 / 실패 이유 / Go·Iterate·Stop.

현재 모든 실행 결과는 미실행이다. 이 자료는 입력·정답·평가 규칙을 준비한 것이며 수집기 구현이나 Windows PoC 성공을 의미하지 않는다.
