# Windows PoC 인수 시나리오

상태: 설계 검토용, 전부 미실행. PM Skills test-scenarios 지침의 목적·시작 조건·역할·행동/결과·경계를 적용했다. [구현 설계](../superpowers/specs/2026-10-16-windows-local-poc-design.md)와 [S-01](03_Windows_대표업무_시나리오.md)을 기준으로 한다.

## TC-01 허용 앱 세션과 전면 앱 전환

목적: 명시적 허용 앱·기록 상태·순서만 안전하게 저장하는지 확인.
시작 조건: 일반 권한 Windows 장비, 지원 앱 설치/버전 기록, 테스트 allowlist, 합성 자료. 역할: 업무 수행자.

1. 준비 상태에서 앱을 전환한다 → 이벤트 없음.
2. 시작 후 브라우저→Excel→편집기로 전환한다 → 지원하는 전환만 순서대로 관찰, 앱 식별과 상태 표시.
3. 비허용 앱으로 전환한다 → 대상 앱 화면/제목/입력 원문 저장 안 됨, 지원 공백 표시.
4. 중복 eventId를 재전송한다 → 저장 개수 증가하지 않음.
5. 종료 후 앱을 바꾼다 → 이벤트 추가 없음, 임의 재개 안 됨.

기대 결과: 이벤트v1의 허용 필드만 직렬화. 빠른 전환을 놓친 경우 이를 완전 수집으로 주장하지 않음.
Core 자동 검증과 Windows 실제 전환 결과는 별도로 기록한다.

## TC-02 정지·잠금·권한 경계

목적: 수집할 수 없는 구간을 정상 기록으로 처리하지 않는지 확인.
시작 조건: TC-01 세션, 수집기 상태/로그 확인 가능. 역할: 수행자·검증자.

1. recording 중 일시정지하고 앱을 전환한다 → pause 제어 이력, 관찰 이벤트/화면 후보 없음.
2. 재개한다 → 새로 관찰한 사실만 기록, 정지 구간을 추측한 절차로 채우지 않음.
3. 잠금·권한 상실·보호 화면을 시험한다 → 중단/공백을 표시하고 우회 시도 없음.
4. 세션20분 경계를 시험한다 → paused와 한도 이유 표시, 이 세션은 한도 초과 후 재개하지 않음.

기대 결과: 화면/API 지원 불가는 실패/미지원으로 보고하며 fake 화면을 정상 수집 증거로 사용하지 않음.

## TC-03 화면 후보 검토·제외·마스크

목적: 사용자가 승인하지 않은 원본이 파일/내보내기에 포함되지 않는지 확인.
시작 조건: 지원 캡처 장비, 합성 민감 문자열을 포함한 화면, 테스트 전용 저장 경로. 역할: 수행자·검증자.

1. 허용 앱의 후보를 만든다 → raw 후보는 메모리에만, 디스크/로그에 원본 없음.
2. 캡처 중 전면 창을 교체한다 → 대상 불일치면 후보 거부 또는 공백 처리.
3. 후보 하나 제외, 다른 하나에 사각 마스크 적용 후 승인한다 → 제외 후보 저장 안 됨, 승인 PNG는 마스크된 새 바이트.
4. 내보낸 PNG를 실제 픽셀로 검사한다 → 제외 영역의 원본 글자/픽셀 미포함.
5. 종료·취소한다 → 후보 접근 불가. 메모리/페이지파일의 포렌식 영구 삭제까지 보장한다고 표시하지 않음.

기대 결과: 파일 목록·writer 경계 검사와 Windows 실제 이미지 검사가 모두 필요. unit만으로 마스크 검증 완료를 선언하지 않음.

## TC-04 한도·쓰기 실패·근거 변경

목적: 자원 부족이나 실패가 성공으로 표시되지 않는지 확인.
시작 조건: Core 가짜 시계/제한 writer, Windows의 이미지 후보 테스트. 역할: 검증자.

1. 후보120개 또는 후보/인코딩 버퍼256MiB 경계를 넘긴다 → paused·원인 표시, 묵시적 후보 폐기/계속 수집 없음.
2. session/asset/export 쓰기를 실패시킨다 → 성공 경로/완료 표시 반환 안 함.
3. 생성 manifest 후 asset을 제외한다 → 이전 입력으로 만든 결과의 승인/내보내기 거부.
4. 승인 후 내용을 수정한다 → 새 revision·재검수 필요. 이미 승인됐다는 이유로 자동 게시 안 됨.

기대 결과: 실패·불완전 저장 범위를 기록하고 데이터/권한 이탈 없이 복구 또는 새 실행을 안내한다.

## TC-05 S-01 실제 기록·template baseline

목적: 자동 수집 pipeline과 업무 결과 검증을 분리.
시작 조건: 원자료 웹/CSV만 참여자에 제공, evaluation 정답은 검증자만 접근, 앱 버전 기록. 역할: 수행자·검토자.

1. S-01을 수행한다 → 원자료12건 중 날짜/승인 조건7건을 집계.
2. 부서별 결과와 합계960,000원을 평가자가 별도 정답으로 검사한다 → 결과 정확성 기록.
3. 허용 근거/주석으로 template 초안을 만든다 → template 모드 명시, 모르는 필터/수식/저장 사실은 확인 질문.
4. 검토·보완·승인 후 export한다 → 승인 Markdown/PNG만, 제외 근거 없음.

기대 결과: 생성기에 정답 금액/필수 단계를 하드코딩하지 않는다. 앱 전환 outline이 만들어졌다는 결과를 AI 문서 품질 성공으로 평가하지 않는다.

## TC-06 provider·후임자 가치 검증

목적: 실제 모델과 재현 실험을 했다면 전체 시도·도움 요청·비용을 측정.
시작 조건: 전송/보관·제공자·비용/시간 상한 검토, 권한 있는 계정, 정답 입력 제외, 참여자 확보. 역할: 검증자·후임자.

1. 기본 template 모드를 실행한다 → 외부 모델 요청 없음.
2. 조건을 갖춘 provider 모드에서 생성한다 → 입력 버전·허용 근거·시도/오류/사용량 기록.
3. 실패·불충분 출력도 포함해 평가한다 → 성공한 시도만 보고하지 않음.
4. 후임자가 정답 없이 매뉴얼로 S-01을 수행한다 → 성공·시간·도움 요청·막힌 단계 기록.

기대 결과: PoC 계획의 Go/Iterate/Stop 판단. 계정/예산/참여자가 없으면 이 시나리오는 차단/미실행이며 성공으로 바꾸지 않는다.
