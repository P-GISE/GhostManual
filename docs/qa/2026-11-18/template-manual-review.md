# 운영 AI 항목 정리 및 양식 매뉴얼 통합 검토

## 운영 실제 AI 검증
운영6268f14의 Aside 브라우저와 합성 양식으로 실제 AI 항목 정리를2회 실행했다. production·AI_ENABLED=true·설정 모델 claude-sonnet-5-5를 확인했고 테스트 transport는 사용하지 않았다. 실제 응답 모델은 fallback 가능성이 있으며 현재 AI_USAGE_LOG 미설정으로 토큰·응답 모델·실비는 계측하지 않았다.

- DOCX는 업무 목적·완료 기준2개를 선택해 AI 항목2개를 받았다. 응답 직후 DB는 review/items0이어서 AI 정리 자체는 저장하지 않는 것을 확인했다. 항목 확정 뒤 ready/items2 및 항목ID가 저장됐고 새로고침에도 유지됐다.
- HWPX는 업무 목적 체크를 해제하고 완료 기준1개만 선택했다. AI가 완료 기준1개를 반환했고 확정 뒤 ready/items1 및 새로고침 보존을 확인했다.
- 같은 문서함 template 일일 사용 카운터가0→1→2로 증가했다. 합성 자료만 사용했고 업무 원문은 새로 전송하지 않았다.
- 첫 확정 양식 정책에 따라 합성 DOCX가 기본 양식이며 HWPX는 기본이 아니다. 두 합성 양식을 사용자 확인용으로 남겼다.
- 화면 DOM·서버 DB로 확인했다. 캡처는 앞선 단계의CDP timeout 이후 재시도하지 않았다.
- 검증 중 새 PR #71에서 박효민의 답변을 확인했다. 새 세션 발급에는 동의했고, 질문을 개인 기록으로 취급해 이동 시 작성자·후임자 질문을 삭제하는 정책을 제안했다. 사용자가 '이동 시 질문 기록 삭제안 수용'으로 확인했다. 후속 이동 기능은 AI 질문/근거를 삭제하되 revision_questions의 변경 질문·답변과 업무·버전·원본·매뉴얼은 보존한다. 현재 운영 기록을 삭제하지는 않는다.

## PR70 검토 범위
PR70은 회사 양식으로 매뉴얼 생성·작성·게시·보기·PDF·후임자 근거 수집을 연결한다. 이 브랜치는6268f14 기준 PR70 b1c649c를 통합한 검토본이다. 원 작성자 브랜치와 운영 코드는 변경하지 않는다.
SQL로 sections를 문단으로 펼치는 경로, draft union 재저장, 게시 규칙·공개 게시본 대체·양식 삭제 후 snapshot 보존을 검토했다.

## 발견 문제와 후속 검증
1. ManualVersionComparison은 항목 이름으로 Map을 만들어 중복 이름 또는 제목/미확인 항목 같은 메타데이터와 충돌하면 변경을 누락한다. 안정적인 항목ID와 별도 메타데이터 키로 구분한다.
2. SourceDetail은 양식 목록 조회 실패를 빈 catch로 숨긴다. 양식 선택 없이 기본형 생성으로 진행되지 않도록 오류·재시도·생성 차단을 적용한다.
3. file-sources의 template draft 재저장 경로는 XLSX/DOCX/HWPX 원본 새 버전 등록과 완료 처리 후 항목·양식 snapshot을 보존하는 통합 회귀를 추가한다.

실행 결과와 CI는 통합 검토 PR에 기록한다. 원 PR70 병합과 운영 반영은 별도 사용자 지시를 따른다.

## PR71 추출 도중 계정/세션 삭제 검토
- document_jobs는 session_id에 직접 FK가 없고 revision/workspace FK로 원본과 연결된다. 개인 문서함이 제거되면 작업도 cascade로 지워진다.
- 문서함이 남고 세션만 사라지면 claimDocumentJob의 유효 세션 검사가 queued/processing을 failed로 바꾼다. 완료 처리도 세션 권한을 재검사해 결과 게시를 거부한다.
- manual_template_jobs는 template 복합 FK이며 세션 FK는 없다. 원본 양식이 삭제되면 작업도 삭제된다. 남은 작업은 유효한 세션/계정 소유자 검사에 실패하면 소비 후 양식을 failed로 바꾼다. 실행 중 lease는 만료/완료 시 검사를 따른다.
- operation_requests도 세션 FK가 없다. 최종 문서/답변 저장 경로의 assertSession이 세션 소멸을 차단한다. processing 행은 lease 만료까지 전역 동시 실행 슬롯을 차지할 수 있어 후속 정리 검토가 필요하다.
- 팀 활성화 후에는 위 소유자 검사에 현재 membership 재검사가 포함돼야 한다. 현재 팀 양식/팀 API의 작동을 검증한 것으로 확대하지 않는다.
