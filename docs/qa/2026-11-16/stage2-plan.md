# 2단계 계획 (2026-11-16)

중간 심사를 통과해 본선에 진출했다. 이 문서는 2단계(11/16~12/18) 범위·일정·역할의 초안이다. 박효민이 작성했고 **박기성과 역할·일정을 아직 합의하지 않았다.** 합의 뒤 이 문서를 고친다.

## 일정과 심사 기준

- 최종보고서와 발표자료 제출: 2026-12-11 (같은 날 함께 제출)
- 본선 시연·시상: 2026-12-18
- 최종 심사(100): 구현 완성도 25, 완성도·실용성 20, AI 활용 고도화·창의성 20, 발표·시연 15, 협업·멘토링 10, 확장성·파급력 10

## 범위

중간보고서에 적은 계획을 줄이지 않고 모두 개발한다.

1. 시연 중 발견한 결함 수정
   - AI 초안이 일부 항목을 비워 게시가 막히는 문제
   - 게시가 막힐 때 이유를 알 수 없는 오류 문구
   - 일부 후임자 질문에서 "AI 출력 형식이 올바르지 않습니다"가 나오는 문제
   - AI가 만든 제목에 "(초안)"이 붙는 문제
2. 회사 양식 기반 매뉴얼 (1순위): 회사의 기존 양식(한글·워드)을 올리면 목차·항목을 읽어 그 양식대로 초안을 쓰고, 근거가 없는 항목은 작성자에게 다시 묻는다.
3. 후속 질문: 답변이 모호하면 AI가 다시 묻는다.
4. 플로팅 후임자 챗봇: 이전 대화를 기억한다.
5. 팀 문서함: 회사별 공간과 권한. 중간보고서에는 설계까지 적었으나 구현을 목표로 한다. 구현 여부는 박기성과 정한다.
6. 한글 OCR 정확도 개선
7. 측정: 합성 업무 사례로 양식 준수율·질문 품질, AI 비용, 서버·스토리지 비용

Dependabot PR(#29·#31·#35·#58)은 첫 주에 처리한다.

## 역할 초안

설계는 박효민이 모두 맡는다. 박기성은 설계를 검토하고 엔진·DB·운영을 구현한다. DB 변경은 관리자 페이지 때처럼 박효민이 설계와 migration 초안을 쓰고 박기성이 검토해 운영에 적용한다.

| | 박효민 | 박기성 |
|---|---|---|
| 설계 | 기능 전체(화면, API, 데이터 구조, 엔진 출력 형식) | 검토(보안, DB, 실현 가능성) |
| 구현 | 화면, API, AI 연동, 결함 수정 | 양식 구조 추출 엔진, OCR, migration 적용, 배포 |
| 문서 | 보고서, 발표자료, AI 비용·품질 측정 | 서버·스토리지 비용 산정 |

설계 문서는 박기성의 작업을 막는 것부터 쓴다: 양식 기반 매뉴얼 → 팀 문서함 → 플로팅 챗봇 → 후속 질문 → OCR 목표.

## 양식 기반 매뉴얼의 현재 안

확정이 아니며 [멘토링 질문](mentoring-questions.md)의 답에 따라 바뀐다.

1. 담당자가 양식을 한 번 등록한다. 여러 개를 저장하고 하나를 기본으로 둔다.
2. 시스템이 양식에서 항목 목록을 뽑아 보여 주고, 담당자가 고쳐서 확정한다.
3. 매뉴얼을 만들 때 고정 항목 대신 그 양식의 항목대로 초안을 쓴다.
4. 답변 기록에 근거가 없는 항목은 지어내지 않고 담당자에게 묻는다.
5. 양식이 없으면 지금의 기본 항목을 쓴다.

정하지 못한 것: 결과물을 화면·PDF로만 낼지, 원래 양식 파일의 칸에 채워 내려받게 할지.

## 위험

- 양식 기능은 프롬프트·화면과 구조 추출이 맞물린다. 첫 주에 추출 결과 형식을 먼저 합의해야 병렬로 작업할 수 있다.
- 팀 문서함은 기존 workspace 권한 구조를 바꾸는 가장 큰 작업이고 동결 직전에 있다.
- 다중 형식 엔진(migration 007)의 운영 반영 상태를 이 문서 작성 시점에 확인하지 않았다.
- 본선은 실시간 시연이라 결함을 우회할 수 없다. 결함 수정을 가장 먼저 한다.
