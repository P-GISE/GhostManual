# GhostManual 중간보고서 — 파일 버전 분석과 운영 복구

운영 루트 EBS 암호화 전환과 새 부팅·기존 서비스 보존·공개 8호스트·새 S3 백업/격리 복원 검증을 완료했다. PR #42는 CI·병합·운영 배포를 마쳤고 PR #43 인쇄 기능을 포함한 실제 실행 SHA는 `1402051`이다. 사용자 승인으로 암호화 EBS를 40 GiB로 온라인 확장하고 비공개 암호화 사전 스냅샷 1개를 보존했다. 11/3 17:45 KST 여유는 약 10.30 GiB였다. 미암호화 원본·이전 스냅샷도 보존 중이며 추가 삭제는 하지 않았다. 아래 전환 전 상태는 당시 이력으로 구분한다. ## 어떤 문제를 해결했나

업무 파일의 이전 버전과 새 버전을 함께 보관해도, 후임자는 어떤 계산식을 왜 바꿨는지 알기 어렵다. GhostManual은 작성자가 새 엑셀 파일을 올릴 때 두 버전의 차이를 찾아 변경 이유를 묻는다. 작성자는 변경 위치를 다시 찾는 수고를 덜고, 후임자는 검수·게시된 매뉴얼에서 업무 판단의 근거를 확인할 수 있다. 이를 위해 박기성은 파일 분석 엔진, 변경 이력을 보존하는 DB, 배포·백업·복구를 담당했다. [제품 방향과 역할 분담](../../99_해야할일.md)

## 파일이 바뀌어도 설명을 추적하는 방법

1. **파일을 읽는다.** 엑셀 엔진은 `.xlsx`의 시트·수식·셀·필터·이름 정의를 시점별 스냅샷으로 만든다. 손상 파일과 매크로 등 위험 요소는 거부한다. 안전성 검사를 통과한 파일이 분석 한도를 넘으면 원본을 보관하고 비교 가능 여부를 명시한다. [엔진 설계와 합성 파일 검증](../../superpowers/plans/2026-10-31-xlsx-engine.md)
2. **변경을 질문으로 연결한다.** 첫 버전에는 용도와 출처를 묻는다. 다음 버전에는 시트·수식·필터·값 등의 변화를 묶어 해당 위치와 이유를 연결한다. 변경 묶음이 10개를 넘으면 앞의 9개를 개별 질문으로 남기고 나머지를 한 질문으로 합친다. 이 규칙은 AI 연결 없이도 작동한다. [질문 생성 코드](../../../src/lib/xlsx/questions.ts)
3. **버전과 권한을 보존한다.** 운영 DB에 적용한 migration 005는 원본 바이트·크기·SHA-256·스냅샷을 버전별로 보관하고, 변경과 질문·답변을 같은 workspace의 revision에 연결한다. 저장한 원본은 갱신할 수 없다. 앱 계정에는 업무 데이터 처리 권한만 부여하고, DB 구조 변경과 백업은 별도 관리자 역할로 분리했다. [migration 005](../../../db/migrations/005_file_versions.sql) · [운영 권한 검증](../../운영_DB권한_외부백업_2026-11-02.md)

배열 수식의 후속 칸에서는 계산 결과가 일반 문자열처럼 보일 수 있었다. 이 때문에 머리글을 포함한 모든 셀 값을 엑셀 AI 입력과 파일 검색 근거에서 제외했다. 제목·시트 구조·변경 수식과 작성자가 직접 남긴 질문·답변은 활용한다. 과거 파일 역시 기존 이력을 덮어쓰지 않고 스냅샷에서 검색 근거를 다시 구성한다. 칸별 이전 값은 소유자만 조회할 수 있다. [배열 수식 회귀와 접근 범위](../2026-11-02/pr32-fixes.md)

## 남은 검증과 공동 제출

S3 저장 암호화와 운영 루트 EBS 암호화 전환을 확인했다. 공유 호스트의 새 부팅·서비스 보존·백업/복원 검증은 완료했고, 미암호화 원본과 스냅샷은 복구용으로 접근을 제한해 보존 중이다. 자동 삭제는 없으며 보존 재검토와 별도 삭제 승인이 필요하다. 이번 40 GiB 확장은 완료했지만 추가 이미지·복구본 삭제와 장기 보관 정책 확정은 별도다. 새 사전 스냅샷 실제 복원은 미검증이다. PDF 검증은 운영 Chrome Owner 합성 텍스트 매뉴얼의 렌더 범위이며 Reader·엑셀 고정 이력·모바일·운영체제 인쇄 창 저장·실물 프린터까지 검증한 것은 아니다. 합성 테스트 자료는 비공개로 유지했고 기존 업무 자료·계정·메일·공유 설정을 바꾸거나 AI를 호출하지 않았다. 이번 원고는 별도 문서 PR로 관리하며 기본 브랜치 반영과 공동 제출은 별도다. 또한 암호화 전환 이후 첫 정규 백업은 11/4 03:20 KST 실행 결과를 확인해야 한다. 일일 백업 사이의 변경분은 복구하지 못할 수 있고, 호스트가 정지하면 같은 호스트에서 보내는 실패 알림도 발송되지 않을 수 있다. [EBS 전환 계획](../2026-11-02/ebs-encryption-plan.md) · [복구 범위와 알림 한계](../../../deploy/backup/README.md)

공동 제출 전에 박효민 담당 자료를 아래 항목에 연결한다. AI의 반복 호출 비용과 한국어 답변 품질은 이번 엔진·운영 검증에서 측정하지 않았다. [공동 보고서 역할표](../../99_해야할일.md)

- [ ] 문제 정의·멘토링 피드백과 이를 반영한 화면 흐름, 운영 시연 영상
- [ ] 질문·초안·후임자 답변별 호출 횟수, 입력·출력 토큰, 측정 조건을 포함한 비용 실측표
- [ ] 합성 업무 사례의 한국어 답변과 평가 기준, 보완할 사례 및 다음 개발 우선순위

이 문서는 공동 보고서에 편입할 박기성 담당 원고다. 공동 통합과 외부 제출은 남아 있다.
