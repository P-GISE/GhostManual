## 글자 수를 확인한 입력 문안 초안

운영 구현·검증 근거에 맞춘 초안이다. 팀 문서와 최종 대조한 뒤 사용하며, 실제 사용 도구와 AI의 역할을 과장하지 않는다. 2단계 공통 문안은 우선 기능을 결정하기 전의 초안이며 기능 선택 자체를 대신하지 않는다.

### 프로젝트명 — 11자 / 허용 1~40자

GhostManual

### 한 줄 소개 — 40자 / 허용 1~60자

업무 파일의 변경 이유를 기록하고 검수된 매뉴얼로 인수인계를 돕는 서비스

### 문제와 대상 사용자 — 185자 / 허용 50~400자

업무 담당자가 바뀔 때 최종 파일과 문서만 전달하면 어떤 수식과 절차를 왜 바꿨는지 알기 어렵다. GhostManual은 엑셀 파일의 새 버전을 비교해 변경 위치와 이유를 연결하고, 담당자가 확인한 내용을 매뉴얼로 게시한다. 반복 업무를 인계하는 작성자와 후임자가 파일을 다시 분석하거나 설명을 반복하는 부담을 줄이는 것이 목표다.

### AI 활용 — 238자 / 허용 100~600자

개발 과정에서 AI 코딩 도구로 코드 검토와 테스트 설계를 보조하고, 제안된 수정은 회귀 테스트와 CI로 확인했다. 서비스에서는 Claude API를 변경 질문과 매뉴얼 초안 생성에 활용한다. 엑셀 비교 자체는 규칙 코드가 수행하며, 엑셀 AI 입력에서 원본 파일과 셀 값은 제외하고 시트 구조·변경 수식·작성자가 남긴 답변 등을 사용한다. 생성한 초안은 담당자가 검수한 뒤 게시하고, 후임자는 게시본과 원본 근거를 확인한다.

### 2단계 공통 초안 — 170자 / 허용 50~300자

선발되면 사용자 검증을 바탕으로 회사 양식 분석과 팀 문서함 중 하나를 우선 선정한다. 선택한 기능의 문서 구조·권한·API 계약을 합의하고 핵심 흐름을 구현한다. 합성 업무 사례로 정확성과 권한 경계를 회귀 검증하고, 기존 백업·복구 및 운영 서비스 보존을 확인한다. 세부 범위는 팀 합의 후 확정한다.

## 결과물 링크 구성안과 확인 사항

1. [운영 서비스](https://ghostmanual.pigs0516.com/) — 공개 랜딩. 개인 문서함은 로그인 필요이므로 핵심 동작은 별도 시연 영상에서도 확인할 수 있어야 한다.
2. **시연 영상 URL — 박효민 자료 대기.** 익명 열람 가능 여부와 3분 이내 권장 조건을 확인한다. 실제 업무 자료 대신 합성 사례를 사용한다.
3. [GitHub 저장소](https://github.com/P-GISE/GhostManual) — GitHub API에서 공개 저장소임을 확인했다. `.env`·토큰·개인 연락처·팀 편집 링크를 결과물 설명에 넣지 않는다.

기존 PDF와 합성 화면 산출물은 대표 사진 후보로 검토할 수 있으나, 최종 대표 사진 선택·공개 권한 확인·업로드는 미완료다. 계정 접근에 필요한 비밀번호나 인증 토큰을 보고서에 적지 않는다.
