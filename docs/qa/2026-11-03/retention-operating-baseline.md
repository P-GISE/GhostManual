# 데이터 보관 운영 기준·검토안 — 2026-11-03

이 문서는 현행 설정과 보존을 위한 검토안을 구분한다. 정책 확정·저장공간 정리·계정/백업/볼륨 삭제의 승인이 아니다. 사용자 요청으로 공간 작업과 복구본 삭제는 보류한다.

## 현행

- 전용 비공개 S3의 postgres/ 백업은 매일 03:20 KST, AES256 저장 암호화, 생성 30일 후 비동기 만료다. 목록·삭제 권한을 앱/백업 역할에 추가하지 않는다.
- 계정 삭제는 기존 사용자 요청 흐름을 따른다. 휴면 계정 자동 삭제를 새로 적용하지 않는다. 기존 세션/공유 링크 만료와 계정 삭제를 구분한다.
- 운영 루트 EBS 암호화는 완료했다. 미암호화 원본 볼륨과 사전/최종 스냅샷은 접근을 제한해 보존한다. 11월 10일 검토 태그는 자동 삭제일이 아니다.

## 보존 검토안 — 실행 전 합의 필요

현재·직전 정상 이미지, 실행/정지/미기동 컨테이너 참조, 활성 배포 영수증과 수동 롤백 기록의 참조는 보존한다. 로컬 복구본 최소 7일은 보호를 위한 제안이며 최초 검토 가능 시점이지 최대 보관 기간이나 삭제일이 아니다.

공간 작업이 다시 승인된 뒤에만 박기성이 배포 안정성, 새 S3 백업의 재다운로드·해시·격리 복원, 호스트 밖에서 현재/직전 설정을 복구할 수 있는지를 확인한다. 하나라도 미충족이면 보존한다. 충족하더라도 정확한 대상과 잃게 될 복구 경로를 설명하고 별도 삭제 승인을 받아야 한다.

보관 목록에는 종류·release·생성일·참조 여부·검증 결과·담당·다음 검토일만 기록한다. 비밀 값·개인 연락처·업무 자료를 복사하지 않는다. 원본/스냅샷 추가 보존 비용은 [EBS 실행 기록](ebs-encryption-cutover.md)을 따른다.

## 복원 시 삭제·회수 정합성

복원은 사용자 트래픽·worker/예약 작업·메일 발송을 차단한 격리 환경에서 먼저 수행한다. 백업 뒤 삭제된 계정/파일과 공유 회수 상태를 대조·반영하고 오래된 세션을 무효화한 뒤 접근 거부를 시험해야 한다. 필요한 이력이 없거나 검증되지 않으면 운영 공개를 재개하지 않는다. 독립 삭제 이력 저장소가 이미 구현돼 있다고 주장하지 않는다.

현재는 EBS 전환 이후 업무 쓰기가 재개됐다. 원본 볼륨으로 단순 복귀하면 이후 변경을 잃으므로 새 쓰기·DB를 보존하고 재반영 방안을 정하기 전 되돌리지 않는다.

## 미결정과 공동 담당 제안

로컬 복구본 최대 보관 기간·예외, 삭제 이력의 저장/접근 권한·보관 기간·담당, 휴면 계정 처리 기준은 팀 합의 대기다. 박기성은 운영 증거·복구 절차, 박효민은 개인정보 안내와 서비스 삭제/공유 동작 정합성을 함께 확인하는 역할을 제안한다. 공동 담당 제안은 합의 완료 표시가 아니다.
