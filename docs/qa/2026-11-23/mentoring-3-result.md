# 3차 멘토링 결과 (2026-11-23)

본선 진출 뒤 첫 멘토링이다. 박효민이 멘토링 자리에서 받아 적은 메모와, 그날 박효민이 정한 방향을 적는다. 작성 2026-11-23, 박효민.

멘토의 말은 메모에 남은 낱말만 옮겼다. 낱말의 뜻풀이는 박효민의 이해이고, 멘토링 일지를 받으면 대조해 고친다.

## 1. 멘토 피드백

| 메모 | 박효민이 이해한 뜻 |
|---|---|
| 소속 부서 여러 개 가능, 프로젝트별 | 한 사람이 부서와 프로젝트 여러 곳에 속할 수 있어야 한다 |
| 권한 섹션화 | 팀에 관리자 한 명과 부관리자가 있고, 둘은 팀의 모든 진행 상황을 볼 수 있어야 한다 |
| 옵시디언, 파일 플로우 방향, 키워드 | 파일과 문서를 옵시디언처럼 한곳에 묶어 보여 주자. 지금은 한눈에 보기 어렵다 |

멘토도 화면을 한눈에 보기 어렵다고 했다. 박효민이 운영 사이트를 둘러보고 느낀 것과 같다. 특히 팀 문서함을 만든 뒤 초대로 가는 길을 찾기 어렵다.

준비해 간 질문 10개에 대한 멘토의 답은 이 문서에 적지 못했다. 멘토링 일지를 받으면 더한다.

## 2. 박효민이 정한 방향

1. **혼자 쓰는 "내 문서함"을 없앤다.** 모든 업무는 팀에 둔다. 혼자 쓰는 사람과 작은 팀은 팀을 하나 만들어 쓴다(1인 팀).
2. **"내 문서함"은 한눈에 보는 화면으로 바꾼다.** 내가 속한 팀마다 어떤 업무와 매뉴얼이 있는지 한 화면에서 보고, 거기서 바로 들어간다. 멘토가 말한 "옵시디언처럼"을 이 화면으로 푼다.
3. **역할 이름을 관리자, 부관리자, 팀원으로 한다.** 권한 구조는 지금(팀 관리자 여러 명, 팀원)을 그대로 쓴다. 팀을 만든 사람이 관리자이고 나머지 팀 관리자가 부관리자다. 차이는 팀 삭제 정도만 둔다.
4. **팀원도 팀의 모든 업무와 매뉴얼을 본다.** 관리자와 부관리자에게는 누가 무엇을 올렸고 어디까지 진행됐는지 보는 진행 현황 화면을 준다.
5. **공유는 매뉴얼 단위가 아니라 팀 단위로 한다.** 후임자는 팀원으로 초대받아 본다. 매뉴얼별 공유 링크를 없앨지는 시안을 보고 정한다. 박효민의 현재 생각은 없애는 쪽이다.
6. **화면 시안을 먼저 만든다.** 개발은 시안을 확인한 뒤 시작한다.

## 3. 작업 순서

기능 동결은 12월 4일이다.

1. 팀 화면에서 초대로 가는 길 정리
2. 한눈에 보는 화면(위 2번)과 그에 따른 메뉴 정리
3. 작성자 후속 질문 구현(DB는 migration 012로 준비됨)
4. 여러 소속과 역할 이름

1, 2, 4번은 같은 화면을 고치므로 시안에서 함께 다룬다.

## 4. 아직 정하지 않은 것

- 개인 문서함에 이미 있는 업무를 어떻게 팀으로 옮길지. 업무 이동 API(#90)는 있다. 가입할 때 1인 팀을 자동으로 만들지, 기존 개인 문서함을 팀으로 바꿀지는 DB 작업이라 박기성과 정한다.
- "팀을 만든 사람"을 지금 DB에서 알 수 있는지. 알 수 없으면 관리자와 부관리자를 구분할 값이 필요하다.
- 공유 링크를 없애면 로그인 없이 읽는 독자 세션과 `shares` 관련 코드, 테스트가 함께 빠진다. 범위와 시기를 박기성과 정한다.
- 멘토 메모의 "파일 플로우 방향"과 "키워드"를 한눈에 보는 화면에 어디까지 넣을지.
- 팀이 부서인지 프로젝트인지 구분해 보여 줄지.

## 5. 팀 확인이 필요한 부분

- 위 2절은 제품 방향을 바꾸는 결정이다. 박기성의 확인이 필요하다.
- 1번과 5번은 세션, 권한, DB에 닿는다. 시안을 확인한 뒤 설계 문서에서 영향 범위를 적는다.
