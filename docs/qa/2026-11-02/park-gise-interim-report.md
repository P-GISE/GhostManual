# 중간보고서 공동 편집본 — 박기성 담당 엔진·DB·서버 운영

**기준 시각은 2026년 11월 2일 21:02 KST다.** 사용자가 업무 파일의 새 버전을 올리면 서비스는 이전 버전과 비교해 무엇을 왜 바꿨는지 묻는다. 박기성은 첫 지원 형식인 엑셀의 비교 엔진, 버전별 데이터를 보존하는 DB 구조, 운영 배포와 복구를 담당했다. 중간보고서 공동 제출 기한인 11월 6일 23:59는 기존 역할표의 제안 일정이다. [역할·일정 원문](../../99_해야할일.md)

## 엑셀에서 변경 이유까지

| 단계 | 엔진이 보장하는 결과 |
|---|---|
| 읽기 | `readXlsx`는 엑셀 원본을 받아 시트별 셀·수식·범위와 이름 정의를 스냅샷으로 만든다. 안전성 검사를 통과했으나 분석 한도를 넘긴 파일은 `limit_exceeded`로 구분해 원본만 보관한다. 손상 파일과 매크로 등 위험 요소는 거부한다. |
| 비교 | `compareSnapshots`는 두 스냅샷에서 시트 추가·삭제, 수식·필터·이름 정의·범위·값 변화를 묶는다. 같은 입력으로 같은 결과를 얻으므로 API가 질문을 해당 버전의 변경 위치에 연결할 수 있다. |
| 질문 | `buildQuestions`는 첫 버전에 용도와 출처를 묻고 다음 버전에는 변경 이유를 묻는다. 변경 묶음이 10개를 넘으면 처음 9개를 개별 질문으로, 나머지를 한 질문으로 합친다. 비교할 수 없는 버전에도 작업 이유를 남길 수 있다. |

이 세 단계는 AI나 DB 없이 실행된다. API·화면이 이 결과를 받아 버전 이력을 저장하고 사용자의 답변을 매뉴얼 작성에 활용한다. 운영에서 5 MiB 업로드 허용과 1바이트 초과 시 HTTP 413 및 추가 버전 미생성까지 확인했다. [엔진 구현](../../../src/lib/xlsx/index.ts) · [엔진 설계·테스트](../../superpowers/plans/2026-10-31-xlsx-engine.md) · [공개 서비스 검증](https://github.com/P-GISE/GhostManual/pull/34)

배열 수식의 후속 칸에는 계산 결과만 남아 일반 문자열과 구분하기 어려운 사례가 있었다. 첫 행의 머리글을 포함한 **모든 셀 값**을 엑셀 AI 입력과 파일 검색 근거에서 제외했다. 제목·시트 구조·변경 수식·사용자가 작성한 질문과 답변은 계속 활용한다. 기존 버전도 원문 이력을 수정하지 않고 저장된 스냅샷에서 검색 근거를 다시 구성한다. 이전 셀 값은 소유자만 열람하며 공개 서비스에서 Reader의 칸별 기록 조회가 HTTP 403으로 거부되는 것을 확인했다. [배열 수식 회귀와 공개 범위](pr32-fixes.md) · [운영 Owner·Reader 검증](https://github.com/P-GISE/GhostManual/pull/34)

## 버전 보존과 DB 권한

운영 DB의 migration 이력에서 `001_initial.sql`부터 `005_file_versions.sql`까지 다섯 건을 확인했다. 005는 버전별 원본 바이트·크기·SHA-256·스냅샷을 `source_files`에 저장하고 변경 묶음과 질문·답변을 같은 workspace의 revision에 연결한다. 원본 크기는 바이트 수와 일치해야 하고 저장 후 원본 갱신을 금지한다. [운영 확인 기록](https://github.com/P-GISE/GhostManual/pull/34) · [적용된 migration 005](../../../db/migrations/005_file_versions.sql)

앱의 운영 접속 역할을 `ghostmanual_app`으로 분리했다. 앱은 서비스 데이터의 조회·등록·수정·삭제 권한을 갖고, 관리자 migration과 백업은 별도 관리 역할로 실행한다. 권한 변경 뒤 합성 계정으로 로그인·프로필 변경·자료 CRUD·매뉴얼 게시·공유와 회수·계정 삭제를 검증했다. 이번 읽기 전용 재확인에서도 앱 역할의 슈퍼유저·DB 생성·역할 생성·public 스키마 생성·migration 이력 수정 권한이 모두 꺼져 있었다. [운영 권한 변경·검증 절차](../../운영_DB권한_외부백업_2026-11-02.md)

## 후속 운영 확인

문서 PR #38은 1ff7609로 병합됐고 CI41440910584는 성공했다. 후속 자동 배포41441959677은 SSM에서 insufficient_disk를 반환하고 앱 교체 전에 거절됐다. 최신 문서 커밋의 실제 반영은 완료로 표시하지 않는다. 제품 앱은 검증한6e02ae6을 유지한다. 현재 여유 약1.26 GiB는 배포기2GiB 조건에 미달한다. 과거7efb284 이미지 한 개의 정리 후보는 독립 검토를 마쳤지만 사용자 승인·writer 반환 전 제거하지 않았다. 공동 보고서 제출 전 최종 배포·공간 상태는 다시 확인한다.
