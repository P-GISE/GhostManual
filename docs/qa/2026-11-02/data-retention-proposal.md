## 팀 결정이 필요한 보관 기준

- **수동 롤백본은 배포 후 7일 보관을 제안한다.** 배포 후 앱·DB 권한·주요 사용자 흐름이 정상이고, 해당 배포 이후 만든 S3 덤프의 재다운로드·격리 복원이 성공해야 정리할 수 있다. 환경·Compose는 S3 DB 덤프에 없으므로 현재 설정과 직전 정상 설정을 별도의 접근 통제된 위치에서 복구할 수 있는지도 확인한다. 7일이 지났는데 조건을 충족하지 못하면 담당자와 다음 검토일을 지정하고 예외 보존한다. 복구가 끝난 임시 다운로드와 최종 복구용 원본을 구분한다.
- **앱 이미지는 현재 운영 이미지와 직전 정상 이미지 각 1개를 최소 보존한다.** 배포 기록에 남은 두 이미지의 digest와 실제 이미지 존재를 먼저 대조한다. 더 오래된 GhostManual 이미지는 실행 중 컨테이너와 승인된 롤백 절차가 참조하지 않을 때만 개별 검토한다. 공유 서버 전체를 대상으로 하는 일괄 정리 명령은 사용하지 않는다.
- **장기 미접속 계정은 현행 유지가 제안이다.** 비활성 기간, 비활성 판단 기준, 삭제 예외와 복구 가능 범위를 아직 정하지 않았다. 다른 정책을 선택하려면 서비스 책임자가 현재 개인정보 안내와의 정합성, 이용자에게 알릴 변경 내용 및 적용 시점을 먼저 결정한다. 수동 롤백본의 7일이나 S3의 30일을 계정에 적용하지 않는다.

## 예전 덤프에서 복원할 때

1. 공개 트래픽·배치·메일 발송을 차단한 격리 DB에 복원하고, 백업 시각과 장애 시각을 확정한다.
2. 백업 이후 계정·자료 삭제 및 공유 회수 내역을 신뢰할 수 있는 최신 운영 상태나 접근이 통제된 복구 기록과 대조한다. 확인된 삭제·회수를 재적용하고 관련 세션도 무효화한다. 현재 문서화된 백업 절차에는 이 변경 이력을 별도로 보존하는 체계가 없다. 비교 근거가 없으면 공개 재개를 보류하고 책임자에게 복구 범위를 보고한다.
3. 삭제 계정 로그인 실패, 삭제 자료 조회 불가, 회수 링크와 기존 Reader 세션 접근 거부를 점검한다. 합성 계정의 정상 접근도 확인한 뒤에만 공개 트래픽을 연다. 보고서에는 시각·처리 건수·성공 여부만 남긴다. 계정 이메일, 사용자 UUID, 원문·링크 토큰과 자격 증명을 내보내지 않는다.

**결정 요청**은 로컬 수동본의 7일·예외 검토 기준, 직전 정상 이미지 보존 기준, 복원 후 삭제·회수 대조 근거의 접근권한·보존 기간·책임자 지정이다. S3의 기존 30일 정책은 이미 승인됐다. 이 문서는 삭제 작업을 실행하거나 비활성 계정 정책을 새로 적용하지 않는다.
