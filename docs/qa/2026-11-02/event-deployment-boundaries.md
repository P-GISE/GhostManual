# 이벤트 배포와 운영 설정의 경계

2026-11-02. 이 문서는 실행 계약을 설명하며 배포 완료 영수증을 대신하지 않는다.

운영 브랜치 `feat/ghostmanual-mvp`의 성공한 push CI가 게시한 `ghostmanual-event-image-<SHA>`만 고정 SSM 명령으로 적용한다. 서버 전체 재부팅이나 DB migration 없이 app 서비스만 교체한다. 정확한 SHA/run/artifact와 실제 image·revision·별도 이벤트 영수증을 함께 확인해야 완료다.

## 유지하는 설정과 데이터

- 운영 `.env`, `compose.yaml`, `compose.no-logs.yaml` 원본은 덮어쓰지 않는다. 검토한 해시와 독립 렌더 모델이 일치하는 root 전용 사본을 사용한다.
- 앱 전용 DB 계정과 원래 메일·Google·AI 설정, DB 볼륨·네트워크를 유지한다. 저장소 기본값으로 운영 설정을 대체하지 않는다.
- 관리자 migration 환경과 정기 백업 서비스는 앱 배포와 별개다. 배포가 관리자 권한을 앱에 주입하거나 백업 타이머를 끄지 않는다.
- `/var/lib/ghostmanual-deploy/deployed.json`은 기존 기록 그대로 보존한다. 기존 run ID는 초기 검토 기준과 정확히 대조하며 그 숫자만으로 CI 이미지 출처를 보증하지 않는다.
- 새 이벤트 기록은 `/var/lib/ghostmanual-deploy/event/deployed.json`에 별도로 남긴다. 실패 시 직전 정상 앱·설정·기록을 대조하고 복구하며 DB·백업·다른 서비스를 초기화하지 않는다.

## 자동 적용과 검토가 필요한 변경

일반 앱·문서 변경은 CI 성공 뒤 이벤트 경로로 검증한다. DB/SQL·Compose·이미지 빌드·배포 실행기·workflow 등 보호 경로가 바뀌면 기존 승인 기준과 다르므로 자동 전환이 거절될 수 있다. 이때 영수증을 지우거나 보호 검사를 낮추지 않고 새 원문·운영 모델을 검토한다.

같은 SHA의 재호출 성공과 새 커밋의 실제 자동 전환은 다르다. 첫 정확 SHA/run 호출 이후 별도 새 운영 커밋의 `workflow_run`, 실제 컨테이너·영수증·DB 연결 권한·다른 서비스·백업 보존까지 확인한다. 기존 앱 배포 polling 타이머는 이 검증 뒤에만 해제하며 DB 백업 타이머는 유지한다.

로그인·메일 수신·Google 인증 왕복·사용자 휴대폰의 모든 동작은 배포 경로 성공과 별도 검증한다. 도구 설치나 CI 성공만으로 전체 기능·보안 해결을 주장하지 않는다.
