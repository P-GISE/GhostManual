# GhostManual 중간보고서 — 서비스·AI·화면 (박효민 담당 원고)

**박효민 · 서비스 계층 담당(기획·API·화면·AI 연동·시연) · 2026년 11월 4일 기준**

공동 보고서에 넣을 박효민 담당 원고 초안이다. 엔진·DB·운영 부분은 [박기성 원고](../2026-11-03/park-gise-report-contribution.md), 제출 화면의 입력 문안은 [제출 인계](../2026-11-03/park-gise-submission-handoff.md)에 있다.

## 1. 문제 정의

담당자가 바뀔 때 보통은 최종 엑셀 파일과 짧은 인수인계 문서만 넘긴다. 후임자는 파일을 열어도 다음을 알기 어렵다.

- 어떤 수식·시트·필터가 언제 바뀌었는지
- 그렇게 바꾼 **이유**가 무엇인지 (거래처 요청, 규정 변경, 실수 수정 등)
- 지금 파일이 검수된 최신본인지

전임자가 매뉴얼을 처음부터 쓰는 것도 부담이다. 일을 하면서 바꾼 이유는 그때 기억하고 있지만, 몇 달 뒤 인수인계 시점에는 잊는다.

GhostManual은 **일하는 동안** 이유를 남기게 한다. 작성자가 엑셀 새 버전을 올리면 서비스가 이전 버전과 비교해 바뀐 위치를 찾고 "왜 바꿨는지"를 묻는다. 답변과 버전 기록이 쌓여 인수인계 매뉴얼 초안이 되고, 작성자가 검수해 게시하면 후임자가 게시본과 근거를 확인한다.

- **대상 사용자:** 반복 업무 파일(정산, 집계, 보고용 엑셀)을 관리하다 인계해야 하는 실무자와 그 후임자
- **해결하려는 것:** 파일 변경 이유의 손실, 매뉴얼을 처음부터 써야 하는 부담, 후임자의 반복 질문

## 2. AI 활용

### 2.1 서비스 안에서 AI가 하는 일

비교 자체는 AI가 아니라 규칙 코드(박기성 엑셀 엔진)가 한다. AI는 그 결과를 사람이 이해하고 답하기 쉽게 만드는 데 쓴다. 모델은 Claude Sonnet 5.5(Anthropic API)다.

| 기능 | AI에 보내는 것 | 보내지 않는 것 | 사람의 역할 |
|---|---|---|---|
| 엑셀 변경 질문·요약 | 시트 구조, 바뀐 수식, 변경 종류·위치 | 원본 파일, **셀 값**(머리글 포함) | 작성자가 질문에 답하거나 건너뜀 |
| 엑셀 매뉴얼 초안 | 시트 구조, 버전별 변경, 질문과 작성자 답변 | 원본 파일, 셀 값 | 작성자가 고치고 검수해 게시 |
| 텍스트 매뉴얼 초안 | 작성자가 입력한 업무 설명 | — | 작성자가 고치고 검수해 게시 |
| 후임자 질문 답변 | **검수·게시된** 매뉴얼과 근거 | 미검수 초안 | 답변에 근거 위치를 함께 표시 |

한글·워드·PPT·PDF·CSV 문서는 규칙 엔진이 바뀐 곳을 찾아 질문을 만든다. 추출한 본문·표 값·OCR 문장은 외부 AI에 보내지 않는다.

설계 원칙:

- **셀 값은 외부 AI에 보내지 않는다.** 칸 단위 변경 기록(이전 값 → 새 값)은 서비스 안에만 저장하고 소유자만 본다. 업무 숫자가 외부로 나가지 않으면서 인수인계에 필요한 이력은 남긴다.
- **AI 초안은 검수 전까지 공개되지 않는다.** 후임자 답변은 게시본만 근거로 쓴다.
- AI가 꺼져 있거나 실패해도 규칙 기반 질문과 직접 작성으로 같은 흐름을 끝낼 수 있다.

### 2.2 개발 과정의 AI 활용

- AI 코딩 도구(Claude Code, Codex)로 설계 문서 작성, 구현, 테스트 설계, 코드 검토를 보조했다.
- AI가 만든 변경도 사람이 확인한 뒤 PR로 올리고, 단위·통합·E2E·접근성 테스트와 CI를 통과해야 병합했다. 예: 문서함 카드 개편(PR #44 → #46)은 단위 133, DB 통합 130, E2E 80, 접근성 81개 테스트를 통과했다.
- 첫 구현에서 엑셀 첫 행의 숫자가 AI 요청에 섞이는 결함을 검토·검증 중에 발견해 고치고 회귀 테스트를 추가했다. AI가 만든 코드를 그대로 믿지 않고 검증으로 걸러낸 사례다.

| 항목 | 계산 | 월 비용 |

| 엑셀 변경 질문 | 10 × $0.0077 | $0.077 |
| AI 초안 | 2 × $0.016 | $0.032 |
| 후임자 답변 | 20 × $0.0123 | $0.246 |
| **합계** | | **약 $0.36 (약 500원)** |

- 사용자 100명이면 월 약 $36(약 5만 원), 1,000명이면 약 $355다.
- 비용의 약 70%는 후임자 질문이다. 줄여야 하면 후임자 답변을 더 싼 모델로 바꾸거나 같은 매뉴얼 부분을 캐싱하는 것이 가장 효과적이다.
- 앱에는 하루 AI 호출 상한(`AI_DAILY_LIMIT`)이 있어 예상 밖 지출을 막는다.

### 3.4 한계

- 같은 시연 파일로 반복 측정해 입력 토큰 편차가 작다. 시트가 많거나 변경이 큰 실제 파일은 입력이 더 커질 수 있다.
- 월 사용량은 가정이며 실제 사용자 데이터가 아니다.
- 한국어 답변 품질은 위 동작 확인 수준이고, 평가 기준을 둔 품질 평가는 아직 하지 않았다.

## 4. 화면 흐름

1. **랜딩** — 서비스 흐름을 한눈에 보여주고 시작하기로 이동
2. **로그인** — 이메일 또는 Google 로그인, 첫 로그인 시 약관 동의
3. **자료 등록** — 업무 파일(엑셀·한글·워드·PPT·PDF·CSV)을 끌어다 놓거나 선택. 이름이 비슷한 기존 엑셀이 있으면 "새 버전으로 올릴까요?"를 먼저 제안
4. **원본 화면** — 버전 목록, 칸 단위 변경 기록(이전 값 → 새 값), AI 변경 질문에 답하기/건너뛰기
5. **매뉴얼 초안** — AI 초안 만들기 → 직접 수정
6. **검수·게시** — 원본 확인 체크 후 버전 게시, 인쇄/PDF 저장
7. **공유·후임자** — 게시본 공유 링크, 채팅형 질문 창에서 여러 번 질문하고 근거와 함께 답변 받기
8. **문서함** — 업무 하나가 카드 하나. 상태(검수 전/게시됨/재검토 필요)와 지금 할 일 버튼(답할 질문 N개, 검수하고 게시 등)
9. **도움말** — 이용 순서를 그림 단계와 FAQ로 안내

### 팀 자체 개선 (사용성 점검)

멘토링 외에 직접 써 보면서 찾은 불편을 고쳤다.

- "자료 등록"과 "새 버전 올리기"가 헷갈림 → 비슷한 엑셀을 등록하면 새 버전으로 올리도록 제안하고, 문서함 버튼을 "새 업무 등록"으로 바꿨다. 엑셀 카드마다 "새 버전 올리기" 버튼과 안내를 넣었다.
- 매뉴얼 초안을 어디서 지우는지 모름 → 문서함에서 여러 업무를 골라 한 번에 삭제(영구 삭제 확인 포함)
- 파일을 고르면 업무 내용 칸이 이유 없이 잠김 → 안내 문구로 대체하고, 잘못 고른 파일을 지우는 휴지통 버튼 추가
- 원본 화면이 길다 → 바뀐 부분을 질문 위로 올리고 시트 미리보기를 접어 둠
- 로그인하면 바로 문서함으로 넘어감 → 랜딩에 머물고 "내 문서함으로" 버튼 제공
- 상단 "질문하기" 메뉴를 없애고 그림으로 된 도움말 페이지로 교체
- 게시된 매뉴얼 인쇄·PDF 저장 (인수인계 문서를 파일로 전달해야 하는 상황)

## 6. 발전 가능성 (2단계 계획)

**우선 기능: 회사 양식 기반 매뉴얼.** 2단계 시작(11/13) 후 먼저 착수한다. AI 활용을 한 단계 높이는 기능이라 우선했고, 팀 문서함은 그다음 순서로 둔다.

| 후보 | 내용 | 담당 |
|---|---|---|
| 회사 양식 기반 매뉴얼 (AI-COMPANY-TEMPLATE) | 회사의 기존 매뉴얼 양식을 올리면 목차·항목·문체를 따라 초안을 만들고 빠진 항목을 묻기 | 박효민(AI·API·화면) + 박기성(양식 읽기 엔진) |
| 팀 문서함 (TEAM-LIBRARY) | 개인 문서함과 별도로 팀이 함께 관리·공유, 역할별 권한 | 박기성(DB) + 박효민(권한 API·화면) |

함께 진행할 후보:

- **작성자 쪽 AI 후속 질문:** 답변이 모호하면 AI가 이어서 다시 묻기
- **플로팅 후임자 챗봇:** 모든 화면에서 열리고 이전 대화를 기억하며, 프롬프트 캐싱으로 비용을 관리
- **OCR 고도화:** 스캔 PDF의 한글 인식 정확도 개선(박기성)
- **AI 비용·품질 고도화:** 실제 크기 파일 측정, 모델 비교, 한국어 답변 평가 기준

사업화 방향(후속): 관리자 화면과 사용량 제한, 팀 단위 월 구독, 회사 로고 적용.
