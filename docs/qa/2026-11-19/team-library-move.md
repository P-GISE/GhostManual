# 팀 문서함 후속 구현 · 2026-11-19

기준은 PR #79 병합본 fb0e262와 운영 migration 009다. PR #71의 승인된 이동 정책을 따른다.

1. 박기성: 이동용 DB 트랜잭션과 회귀부터 작성한다. 현재 공개 이동 API는 연결하지 않는다.
2. 박효민: 팀 멤버십을 확인하고 대상 문서함용 새 세션을 발급한다. 기존 세션의 workspace_id는 변경하지 않는다. 요청과 문서·양식 워커의 완료 단계에서 현재 멤버십을 검사한다. 마지막 관리자 변경·탈퇴·추방은 동일 workspace 잠금으로 직렬화한다.
3. 박기성: API 연결 후 세션 전환, 역할별 접근, 공유 링크 재진입과 업무 이동을 통합 검증하고 배포한다.

운영 DB 카탈로그를 읽기 전용으로 조회했다. published_version_fk 외에 이동 관련 복합 FK는 즉시 검사되며, 원본 revision·게시본·파일·변경 그룹·문서 추출 결과에 불변 트리거가 있다. document_jobs와 document_results도 source_files의 문서함/리비전 키에 연결된다. 단순히 sources.workspace_id만 바꿀 수 없다.

- 다음 migration은 010 후보로 두고 시작 직전 번호를 재확인한다. 이동에 참여하는 복합 FK만 지연 가능하도록 검토하며 일반 쓰기의 즉시 검사와 기존 불변성을 유지한다.
- 구·신 문서함 잠금 순서를 고정한다. 이동 중 취소·실패 시 변경 전체를 되돌린다. 양측 권한, 대상 용량과 진행 중인 추출·AI 작업을 같은 트랜잭션에서 검사한다.
- evidence와 질문 결과 JSON의 evidence/searchResults를 함께 찾아 관련 AI 질문 전체와 재조회 캐시를 제거한다. 복합 인용도 포함한다. revision_questions의 업무 변경 질문·답변과 게시본은 보존한다.
- 공유 행과 링크 토큰은 보존한다. 기존 Reader 세션은 되돌릴 수 있는 격리 테스트에서 폐기 후 같은 링크 재진입으로 새 Reader 세션을 발급하는 방향을 검증한다. 현재 Reader 세션은 shares에 복합 FK로 묶이고, 뒤에 질문·근거가 삭제 연쇄로 연결된다.
- 회귀 기준은 자료·원본 바이트·리비전·변경 질문/답변·게시본 동일성, 관련 AI 질문 및 캐시 제거, 무관 질문 보존, 공유 링크 재발급, 권한 철회·용량 초과·동시 업로드·중간 실패 시 전체 롤백이다.

이번 점검에서는 운영 기록 변경이나 migration 실행을 하지 않았다.
## 구현 상태

원격 브랜치에 010과 격리 회귀를 추가했다. move_personal_source(actor, source, target)는 마이그레이션 소유자용 DB 진입점이다. PUBLIC 실행 권한은 회수했고 앱 역할에는 실행을 부여하지 않았다. 팀 멤버십을 검사하고 순서대로 양쪽 문서함을 잠근다. 이동에 필요한 FK만 트랜잭션 안에서 지연시키며 게시 버전 FK의 기존 동작은 유지한다.

기존 링크의 토큰과 만료 시간은 보존한다. 이동 이전 Reader 세션은 제거되므로 같은 링크로 다시 들어가 새 Reader 세션을 발급한다. 기존 비이동 질문과 사용량은 유지한다. 010을 운영에 적용하거나 공개 API를 연결하지 않았다.
