# 문서 추출 완료 감지 지연 개선

기준: PR #122 병합 2cb50e5. 운영 배포·migration 014·워커·AI 설정 변경 제외.
기존 완료 확인은 2초마다 무거운 상세 API를 읽어 격리 native 측정 약2.3초였다.

## 설계와 판단
소유자(현재 팀원 포함) 전용 상태 API는 revisionId/status만 반환한다.
매 요청 기존 세션·멤버십을 재검증하고 문서함 잠금 뒤 문서함/자료/버전을 함께 제한한다.
Reader는403, 다른 문서함은404, 만료·회수된 세션은401이다.
250/500/1000/2000ms 순차 대기 후 상태를 읽고 최대2초 간격을 유지한다.
종료 상태를 확인한 뒤 기존 상세 API로 다시 권한을 검사한 결과만 화면에 적용한다.
원문·질문·공유·다운로드·게시 권한은 상태 응답으로 해제하지 않는다.
오류는 자동 반복하지 않고 명시적인 읽기 재시도만 제공한다. 선택 변경/언마운트는 요청과 타이머를 취소한다.

Ruling: 지속 연결/SSE 대신 경량 progressive polling을 사용한다. 기존 프록시·DB 권한·프로세스 구조를 유지하기 위해서다.
비용: 초기 상태 요청이 추가되고 긴 OCR의 최악 감지는 여전히 약2초다. native와 긴 작업 개선을 혼동하지 않는다.

## 순서와 완료 기준
1. 새 상태 API 계약과1200ms 화면 감지 E2E를 현재 앱에서 실패하는지 확인한다.
2. 작은 status/helper/component를 추가하고 FileVersions의 기존 interval만 교체한다.
3. 시간 간격·순차 요청·취소·오류 재시도 및 권한 회수 회귀를 검증한다.
4. 동일 runner/DB013/변경 없는 하네스로 기준과 후보를 각각30회 측정한다.
5. 전체 CI·독립 최종 검토와 프로젝트 가이드 갱신 후 새 PR을 남긴다. 병합·운영 반영은 별도다.
