# GhostManual 배포 구성 검토

작성일: 2026-10-03
상태: 조사 결과 및 설계 제안. 구현·배포 완료 문서가 아님.

## 사용자 요구

- 두 첨부 프롬프트를 기준으로 신규 프로젝트를 제작한다.
- 심사위원이 공개 URL로 접속할 수 있어야 한다.
- 사용자 소유 AWS, Cloudflare, Tailscale, GitHub를 활용한다.
- 기존 도메인의 GhostManual 서브도메인을 사용한다.
- 자료 입력 → AI 구조화 → 매뉴얼 초안 → 사람의 수정·저장 → 질문 → 근거 검색 → 답변·출처 확인을 구현한다.
- 원본 Source, 사람이 검수한 Manual, 근거를 가진 Answer를 구분한다.

## 확인된 사실

| 항목 | 관찰 결과 | 근거 |
|---|---|---|
| 로컬 프로젝트 | 제품 소스와 Git 저장소 없음 | 루트 목록 및 이전 Phase 0 Git 확인 |
| 도메인 | pigs0516.com 등록 | Cloudflare 도메인 및 DNS 화면 |
| DNS | 11개 레코드 중 ghostmanual 레코드 없음 | Cloudflare DNS 전체 목록 |
| 기존 터널 | 루트 및 www가 lostark-party-aws 터널을 참조 | Cloudflare DNS 화면 |
| GitHub | CLI 인증 계정 P-GISE | gh api user --jq .login |
| 저장소 | 조회한 10개 저장소에 GhostManual 없음 | gh repo list P-GISE --limit 50 |
| Tailscale | lostark-party-aws Linux 장비 등록 | tailscale status |
| 사용자 제공 장비 링크 | lostark-party-windows Windows 장비, Connected 표시 | Tailscale 해당 장비 화면 |
| AWS | 계정 콘솔 열람 가능, SSH 읽기 전용 조회 성공 | 사용자 제공 AWS 콘솔·Tailscale SSH |
| 서버 자원 | 메모리1906MB/가용805MB, 디스크여유13GB, Docker29.5.3 | 2026-10-03 free/df/docker version |
| 포트 | 3000·3100 사용 중,3100은 EventOps | docker ps 및 ss -ltn |

계정 연락처, 인증키, 토큰은 이 문서에 기록하지 않는다.

## 미확인

- 실제 EC2 상품 사양·리전·요금과 GhostManual 추가 부하 적합성. 남은 메모리·디스크 관찰값은 위 표에서 확인했다.
- SSH 조회 권한은 확인했으며 새 서비스·DB 생성은 아직 수행하지 않았다.
- 기존 터널의 현재 연결 상태와 실제 origin 구성.
- 사용 가능한 AI 제공자 및 API 자격 증명, 사용량 예산.
- 데이터 보관 기간 및 운영 담당자 정보.

## 접근 방법 비교

1. 기존 AWS 서버에 별도 서비스 배포: 우선 권장. 기존 운영 자산 활용 가능. 여유 용량과 서비스 분리를 확인해야 한다.
2. 신규 AWS 서버에 전용 배포: 기존 서비스와 장애 범위 분리가 명확하다. 추가 비용과 설정이 필요하다.
3. Windows 장비에서 호스팅하고 Cloudflare Tunnel로 공개: 초기 시연에 활용할 수 있으나 PC 전원·재부팅·가정 회선에 의존한다.

## 제안 구성

- 목표 호스트명: ghostmanual.pigs0516.com. 아직 DNS를 생성하지 않았다.
- 공개 접속: 방문자 → Cloudflare HTTPS/Tunnel → GhostManual 애플리케이션.
- 운영 접속: 개발자 → Tailscale → 배포 서버.
- 코드 저장: P-GISE 아래 GhostManual 전용 저장소. 아직 생성하지 않았다.
- 기존 AWS 서버 사용은 용량·권한 조사 후 확정한다.
- 기존 서비스와 앱 디렉터리, 포트, 데이터 저장소를 분리한다.
- 실제3100 포트 충돌 확인 후 앱 바인딩 제안을127.0.0.1:3200으로 수정했다.
- DB를 공개 인터넷에 노출하지 않는다.
- 단일 웹 애플리케이션과 관계형 DB를 우선 검토한다. 구체 프레임워크와 버전은 후속 설계에서 결정한다.
- 최초 입력은 직접 텍스트와 텍스트 파일을 우선 제안한다. PDF·Word·Excel 파서는 핵심 흐름 후 확장 여부를 결정한다.
- 공개 데모는 합성 자료를 사용하며, 방문자별 작업 영역을 분리한다. 실제 내부 자료는 인증된 영역에서만 처리하도록 설계한다.
- AI 실패 시 실패 상태와 원문·검색 결과를 표시한다. 근거 부족은 별도 정상 응답 상태로 처리한다.
- 초안과 검수 완료 매뉴얼을 구분하고, 답변이 참조한 매뉴얼 버전과 원문 위치를 보존한다.

## 검증 계획

자료 등록부터 출처 열람까지 브라우저에서 검증하고, 재접속 후 저장 유지·사용자 간 데이터 분리·근거 없는 질문·AI 장애·원본 수정 시 기존 매뉴얼의 재검토 상태를 검사한다. 단위 테스트, 통합 테스트, lint, typecheck, build 결과를 별도로 기록한다.

## 의사결정 상태

공개 웹 배포 및 보유 인프라 활용은 사용자가 지정했다. 이후 상세 설계를 작성하고 사용자의 가이드 업데이트·계속 진행 요청으로 상세 설계 승인을 반영했다. 구현 계획을 작성했으며 계획 검토·실행 방식 확인이 다음 단계다. 서버 자원 조회는 성공했지만 추가 앱 부하 적합성은 미확인이다. 아직 앱 생성, 의존성 설치, 서버 변경, DNS 변경을 수행하지 않았다.
