# 위험요소 및 개선포인트

## 2026-10-22 파일 버전 방향의 위험 (설계 단계)

- 질문 폭주: 대량 변경이 질문 수백 개가 되면 쓰지 않게 된다. 묶음·우선순위·업로드당 10개 상한으로 대응하고 실제 사용 후 조정한다.
- 과정 정보 부재: 결과 차이만 보이므로 작업 순서·되돌린 시도·파일 밖 흐름은 모른다. 목적·자료 출처 기본 질문으로 보완하며, 의도를 추측해 사실처럼 표시하지 않는다.
- 업로드 누락: 사용자가 올리지 않으면 기록이 없다. 알림 등 보완은 후속 검토다.
- 악성·과대 파일: 매크로·암호·외부 엔티티·압축 폭탄·상한 초과를 저장 전 거부한다. 현재 앱 메모리 한도 안에서 실제 측정이 필요하다.
- 악성 파일 전달 통로: 1단계는 여러 형식을 저장해 Reader에게 내려받기로 전달한다. 허용 목록·형식 서명 검사·매크로/실행 파일 거부·attachment+nosniff로만 내보내고 브라우저에서 열지 않는다.
- 비교 미지원 형식의 가치: Word·PDF 등은 버전과 답변만 남아 차별점이 약하다. "비교 미지원"을 분명히 표시하고, 많이 쓰는 형식부터 2단계 비교를 늘린다.
- 민감 정보: 셀 값은 사용자가 올린 업무 자료이므로 저장하되 로그·오류에 남기지 않고 기존 7일 만료·삭제 정책을 따른다.
- 차별성: 단순 파일 버전 저장과 다르게 보이려면 변경 질문·답변과 매뉴얼 연결이 실제로 쓸모 있어야 한다. 합성 시나리오로 확인한다.

## 2026-10-19 배포 후 확인 범위

배포 전의 IP 혼동은 사용자 실제 status/SSH 출력으로 AWS100.97.248.52를 확인해 정정했다. Windows에서 GitHub 로그인 후 기존 artifact를 확보하고 ZIP/전달 파일 해시·OCI manifest/config 관계를 검증했다. 소유자ubuntu·600인.env는 root·600으로 맞춘 뒤 앱만 교체했다. 공개8화면의 폰트·정렬·키보드 개선과 사용자 서버 출력의 DB/기존 서비스 보존을 확인했다. [최종 근거](qa/2026-10-19/deployment-complete.md)를 따른다.

현재 클라우드의 raw TCP/게시 제어 제약은 남아 있지만 Windows SSH로 완료한 이번 배포를 미완료로 되돌리지 않는다. 전체 소스 재현성·서명 검증, 지속 부하·실기기/전체 접근성 인증은 별도 범위이며 실제 AI는 계속 사용자 지시로 제외한다.

## 2026-10-19 배포 전 확인된 차단과 공개 미적용

TCP grant가 비어 있고 proxy8088 연결 거부로 실제 SSH가 인증 전 실패했다. 이것을 SSH 키 부재·Tailscale 정책 거부·Check 인증 실패로 단정하지 않는다. artifact API는 프록시403으로 차단되어 만료/이미지 ID를 새로 확인하지 못했다. 공개 Chromium8화면에서 Pretendard와 본문 main 포커스 개선의 미적용을 직접 확인했다. 공개200은 새 배포 성공 또는 DB/3000/3100 정상의 증거가 아니다. [직접 실행 기록](qa/2026-10-19/deployment-check.md)에 범위와 재개 조건을 구분한다. 전체 인터넷 허용·키 교체·환경 삭제는 요구하지 않는다.

## 2026-10-17 공개 검증 후 남은 위험
