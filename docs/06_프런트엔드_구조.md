## UI 동작 기준
- 첫 화면은 제품 시작과 자료 목록 중심. 샘플은 합성 자료임을 표시한다.
- 초안/검수 완료/재검토 필요를 색상과 글자로 구분한다.
- 원문을 보며 항목별 수정 가능. 원본 인용과 담당자 추가를 구분한다.
- 질문 결과에는 답변, 단계, 근거, 원본 위치, 미확인 항목을 함께 표시한다.
- 로딩은 실제 요청 중 상태만 표시하고 숫자 진행률을 만들지 않는다.
- 400 필드 오류, 409 충돌, 429 제한, 503 장애마다 다음 행동이 다르다.
- 최소 입력 제한은 UI와 서버가 같은 schema를 사용한다. 서버 검증을 생략하지 않는다.
- 키보드 tab 순서·focus·label·오류 연결·live region, 390px/1440px 검사.
- Markdown/AI 응답은 기본 텍스트로 렌더링하고 임의 HTML을 실행하지 않는다.

## 2026-10-24 시작 후 세션 확인과 문서함 오류 분리

빈 공간·합성 예제 생성의 201 응답만으로 문서함에 이동하지 않는다. 업무 본문 없는 기존 GET /api/session을 캐시 없이 조회하고 role=owner 및 생성 응답의 expiresAt 일치를 확인한 뒤 이동한다. 10초 내 확인되지 않거나 401·403·503·형식 오류가 발생하면 시작 화면에서 세션 다시 확인(GET만)과 Safari/Chrome에서 열기 안내를 제공한다. 같은 화면에서 재시도해도 공간 생성 POST를 반복하지 않는다. 만료시각 일치는 이전 세션을 걸러내는 보강이며 workspace 고유 식별 증명은 아니다.

문서함의 인증·조회 실패는 정상 빈 목록과 구분한다. 401은 시작 화면·외부 브라우저 안내, 기타 조회 실패는 다시 불러오기를 제공한다. 조회가 실패했을 때 빈 목록 안내와 문서 추가·영구 삭제 영역을 표시하지 않는다. 쿠키 HttpOnly/Secure/SameSite=Lax, 만료·Origin 정책과 DB는 변경하지 않았다.
