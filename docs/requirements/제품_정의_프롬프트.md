# GhostManual 프로젝트 정의 및 제품 방향 프롬프트

당신은 지금부터 **GhostManual 프로젝트를 이해하고 설계하고 구현하는 AI 개발 에이전트**다.

GhostManual을 단순한 AI 문서 요약 서비스, 일반적인 챗봇, 사내 검색 서비스, 파일 업로드형 RAG 서비스로 해석하지 않는다.

GhostManual의 핵심 목적은 다음과 같다.

> **사람에게만 남아 있는 업무 경험과 암묵지를 조직이 지속적으로 사용할 수 있는 업무 매뉴얼로 변환하고, 이후 다른 사람이 필요한 순간 자연어로 질문하면 실제 업무 자료와 매뉴얼을 근거로 업무 방법을 안내하는 AI 기반 업무 인수인계 및 조직 지식 관리 시스템**

GhostManual에서 AI는 단순히 글을 생성하는 도구가 아니다.

AI의 역할은 다음과 같다.

**흩어진 업무 정보 수집**
→
**업무 내용 이해**
→
**업무 지식 구조화**
→
**업무 매뉴얼 생성**
→
**사람의 검토 및 수정**
→
**조직 지식으로 저장**
→
**후임자의 질문 이해**
→
**관련 업무 지식 검색**
→
**근거 기반 답변 제공**

GhostManual의 최종 목적은 다음 한 문장으로 정의한다.

> **사람이 떠나도 업무 지식은 남는다.**

---

# 1. GhostManual이 해결하려는 문제

기업과 조직에서는 업무가 시스템보다 사람에게 의존하는 경우가 많다.

실제 업무 정보는 다음과 같은 형태로 흩어져 있다.

담당자의 머릿속  
구두 설명  
카카오톡  
Slack  
Microsoft Teams  
이메일  
Excel  
Word  
한글 문서  
PDF  
Notion  
Google Drive  
사내 NAS  
업무 시스템  
ERP 사용 경험  
개인의 메모  
전임자가 만들어 둔 파일

문제는 이러한 자료 자체가 존재한다고 해서 업무 지식이 제대로 보존되는 것은 아니라는 점이다.

예를 들어 다음과 같은 파일이 존재할 수 있다.

`2026_급여정산.xlsx`

하지만 새로운 직원은 이 파일만 보고 다음을 알기 어렵다.

언제 사용해야 하는지

어떤 데이터를 먼저 확인해야 하는지

어떤 순서로 처리해야 하는지

특정 셀을 왜 수정해야 하는지

실수하면 어떤 문제가 발생하는지

누구에게 확인을 받아야 하는지

예외 상황에는 어떻게 대응해야 하는지

업무가 끝났다는 기준이 무엇인지

이러한 정보는 대부분 담당자의 경험에 의존한다.

GhostManual은 바로 이 문제를 해결해야 한다.

# 2. 핵심 문제 정의

GhostManual이 해결해야 하는 핵심 문제는 다음과 같다.

## 문제 1. 업무 지식의 개인 의존

회사 업무가 특정 담당자의 경험과 기억에 의존한다.

담당자가 퇴사하거나 부서를 이동하면 업무 지식 역시 함께 사라질 가능성이 있다.

---

## 문제 2. 인수인계 문서 작성 비용

직원이 직접 업무 매뉴얼을 작성하는 것은 시간이 많이 소요된다.

또한 사람이 직접 작성하다 보면 다음과 같은 문제가 발생한다.

작성 자체를 미룸

중요한 내용을 빠뜨림

본인에게 너무 익숙한 내용을 생략함

파일 위치만 적어 놓음

최신 정보가 반영되지 않음

업무 흐름이 아니라 단순 목록만 작성됨

따라서 GhostManual은 매뉴얼 작성 부담을 줄여야 한다.

---

## 문제 3. 기존 문서는 검색하기 어렵다

매뉴얼이 존재하더라도 긴 문서를 처음부터 읽어야 할 수 있다.

후임자가 실제로 원하는 것은 대부분 전체 문서가 아니라 특정 질문에 대한 답이다.

예:

"신규 거래처 등록은 어디에서 해요?"

"급여 정산 전에 확인해야 하는 게 뭐예요?"

"결제 취소 요청이 들어오면 어떻게 처리해요?"

"이 오류가 발생하면 누구에게 연락해야 해요?"

GhostManual은 이런 질문에 필요한 업무 지식을 찾아 제공해야 한다.

---

## 문제 4. 기존 생성형 AI는 근거 없는 답변을 할 수 있다

일반적인 AI 챗봇은 회사 내부 업무를 정확히 알지 못한다.

하지만 자연스러운 문장을 생성할 수 있기 때문에 사용자가 잘못된 답변을 신뢰할 가능성이 있다.

따라서 GhostManual에서는

**그럴듯한 답변보다 확인 가능한 답변**

을 더 중요하게 본다.

## Manual

Source를 기반으로 AI와 사람이 함께 만든 구조화된 업무 매뉴얼.

Manual은 단순 요약이 아니다.

실제로 다른 사람이 업무를 수행할 수 있도록 작성되어야 한다.

---

## Answer

사용자의 질문에 대해 Manual과 Source를 검색하여 제공되는 답변.

Answer는 가능하면 어떤 Manual 또는 Source를 사용했는지 표시해야 한다.

반드시 사람이 확인할 수 있어야 한다.

기본 흐름:

→

→

수정

→

→

# 9. GhostManual 질문 시스템

Knowledge Consumer는 자연어로 업무를 질문할 수 있어야 한다.

예:

"이번 달 급여 정산은 언제 해야 해?"

"거래처에서 계산서 수정 요청이 왔는데 어떻게 해야 해?"

# 11. Hallucination 방지 원칙

GhostManual에서는 답변을 만들어내는 것보다 **모르는 것을 모른다고 말하는 능력**이 중요하다.

근거가 부족하면 추측하지 않는다.

예:

잘못된 방식:

"해당 상황에서는 ERP 관리자 메뉴에서 승인하면 됩니다."

근거가 없다면 이렇게 답한다.

"현재 등록된 업무 매뉴얼에서 해당 절차에 대한 근거를 확인하지 못했습니다."

가능하다면 다음 행동도 안내한다.

예:

관련 담당자에게 문의

추가 업무 문서 등록

기존 매뉴얼 업데이트

---

# 12. 질문 답변 예시

사용자:

"이번 달 급여 정산은 언제 시작해야 해?"

GhostManual:

"현재 등록된 급여 정산 매뉴얼에서는 매월 25일 전후에 급여 정산 업무를 시작하도록 안내하고 있습니다.

먼저 해당 월의 근태, 휴가, 휴직 정보를 확인한 뒤 수당 자료를 검토합니다.

근거:
급여 정산 매뉴얼 > 업무 일정
급여 정산 매뉴얼 > 사전 확인 사항"

---

# 13. 근거가 부족한 질문 예시

사용자:

"해외 직원 급여는 어떻게 계산해?"

관련 자료에 해외 직원 정보가 없는 경우:

"현재 등록된 급여 관련 매뉴얼에서는 해외 직원 급여 계산 절차를 확인할 수 없습니다.

국내 직원 급여 절차는 등록되어 있지만 해외 직원에게 동일하게 적용된다는 근거는 없습니다.

추가 매뉴얼 등록 또는 담당자 확인이 필요합니다."

이것이 GhostManual이 지향해야 하는 답변이다.

---

# 14. GhostManual은 단순 RAG 서비스가 아니다

GhostManual에서 RAG는 하나의 기술적 수단일 뿐 제품 자체가 아니다.

단순 RAG 서비스:

문서 업로드

→

Embedding

→

Vector Search

→

LLM 질문

GhostManual:

업무 자료 입력

→

업무 지식 추출

→

구조화된 Manual 생성

→

담당자 검수

→

지식 저장

→

후임자 질문

→

Manual + Source 검색

→

근거 기반 답변

→

지식 부족 발견

→

Manual 개선

GhostManual에서는 **지식 생성과 지식 소비가 하나의 사이클**을 형성해야 한다.

# 36. 최종 제품 철학

GhostManual은 AI가 사람을 대신해 업무를 수행하는 시스템을 목표로 하지 않는다.

GhostManual은

**사람이 가진 업무 경험을 다음 사람에게 전달하는 시스템**

을 목표로 한다.

AI는 조직 지식을 생성하는 최종 권위자가 아니다.

AI는

정보를 찾고

정리하고

구조화하고

검색하고

설명하는 도구다.

업무 지식의 최종 판단과 검수는 사람에게 남아 있어야 한다.

따라서 GhostManual이 지향해야 할 최종 구조는 다음과 같다.

**Human Knowledge**

↓

**AI Structuring**

↓

**Human Verification**

↓

**Organizational Knowledge**

↓

**AI Retrieval**

↓

**Evidence-based Answer**

↓

**Human Action**

모든 기능과 기술 선택은 이 구조를 기준으로 판단한다.
