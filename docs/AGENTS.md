# 프로젝트 작업 지침

사용자 지시가 기본 절차보다 우선한다. 작업 전 [프로젝트 맥락](PROJECT_GUIDE.md)과 [문서 가이드](00_문서_가이드.md)를 읽는다.

이 저장소는 초기화됐다. 제품 코드·테스트·DB·배포 설정이 존재하거나 기술 선택이 승인됐다고 가정하지 않는다. 기존 Git 이력은 복구용이며 새 요구사항의 근거가 아니다.

요청을 99에 등록하고 작업 영역의 01~09 문서를 작성한다. 실제 확인·검증 결과는 10에 남긴다. 사용자 승인 이력을 추정하거나 실행하지 않은 검증을 통과로 쓰지 않는다.

개발 절차는 Superpowers를 사용하고 LazyCodex는 선택한 작업에서만 대체 절차로 사용한다. 동일 작업에 두 오케스트레이터를 중복 실행하지 않는다. [개발 도구 가이드](개발_도구_가이드.md)를 참고한다.

코드 인덱스가 생성된 경우 CodeGraph로 먼저 탐색한다. `.codegraph/`가 없으면 기존 인덱스가 있다고 가정하지 않는다. 도구 캐시·보고서·자격증명은 Git에 넣지 않는다. 비밀 값은 읽어 출력하거나 채팅·문서·로그에 기록하지 않는다.

운영 서버·실제 DB·DNS·기존 서비스는 별도 작업 범위로 취급한다. 프로젝트 파일 초기화만으로 운영 환경 삭제나 배포를 수행하지 않는다.
