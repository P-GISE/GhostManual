# 프로젝트 맥락

갱신일: 2026-10-16. 현재 단계는 **Task1 Core 구현·단위 검증 후 Windows 관찰 단계 준비**이다.

## 사용자 결정

- AGENTS와 00~10·99 문서 전체를 “프로젝트 가이드”라고 부른다.
- 상세 가이드는 docs 폴더에 모으고 루트 AGENTS는 문서 진입점만 둔다.
- 개발 도구와 빈 제품 설계 가이드를 유지하고 기존 앱·테스트·DB·배포 설정·작업 기록을 제거한다.
- 이전 제품 범위·기술 선택·승인·검증 결과를 새 프로젝트에 자동 승계하지 않는다.
- 사용자 선택: “GhostManual을 처음부터 다시 설계 — 요구사항 추가 예정”.
- 핵심 목적: 업무 수행 과정을 자동 수집해 인수인계 매뉴얼을 만드는 서비스.
- 첫 PoC 수집 범위: PC 전체 업무의 화면·여러 앱 작업 흐름. 첫 지원 OS는 Windows로 사용자 확인.
- 첫 대표 업무는 최신 응답인 웹 자료 조회 → Excel 정리 → 결과 문서 작성으로 반영한다. 앞서 응답한 파일 탐색기·문서·메일 업무는 확장 후보로 구분한다.

## 검증 단계와 완료의 의미

| 단계 | 증명할 내용 | 현재 상태 |
|---|---|---|
| A: 순수 Core | 세션 상태·이벤트 계약·중복 방지·로컬 저장의 단위 검증 | Task1 Linux 단위 검증 통과. manifest/export는 후속 작업 |
| B: Windows 메타데이터 | 실제 전면 앱 전환·일시정지·잠금·실패 기록 | 미구현·실 장비 미확인 |
| C: 화면·내보내기 | raw 이미지 비저장·마스킹·승인 근거만 저장/내보내기 | 미구현·미실행 |
| D: 업무 가치 | 실제 모델 조건·후임자 재현·품질/시간/비용 판단 | 미실행 |

A 통과만으로 B~D를 완료 처리하지 않는다. 템플릿 초안 생성은 관찰 정보의 연결을 검증하는 baseline이며 실제 모델 품질이나 인수인계 효용의 근거가 아니다. 구매 요청 12건의 합성 정답은 평가 자료이며 생성기 입력이나 제품 기능으로 고정하지 않는다.

## 다음 단계

사용자의 “이제 진행해 다음꺼” 지시에 따라 Task1 Core 구현을 진행했다. .NET10은 Core 구현 기준으로 채택했으며 Windows11/WPF·화면 정책의 실제 지원 검증은 남아 있다.

1. Windows 장비·버전·브라우저/Excel/문서 앱·권한을 확인하고 Task2 observer/UI를 구현·실험한다. 이 Linux 환경에는 실제 Windows 검증 경로가 없어 Task2 실행은 차단으로 기록한다.
2. Task3은 Windows Graphics Capture 기술 probe 이후 화면 후보·검토·마스크·승인 경계를 구현한다.
3. Task4에서 템플릿 초안·승인 revision 내보내기·S-01을 검증한다. 실제 모델·전송·예산·후임자 평가는 별도다.
4. 실제 관찰 결과로 MVP·물리 DB/API·배포 구성을 결정한다.

저장 일관성을 위해 세션 루트의 current.json이 가리키는 불변 snapshot 안에 session.json/events.jsonl/controls.jsonl을 함께 보존한다. 이전 snapshot은 유지하므로 세션 삭제/보관 정책은 후속 구현이 필요하다. 전체 PC 수집·자동 매뉴얼 생성이 완성됐다는 의미는 아니다.

실제 작업 상태는 [99](99_해야할일.md), 확인 근거는 [10](10_파일_점검_현황.md)에 기록한다.
