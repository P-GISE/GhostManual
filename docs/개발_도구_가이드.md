# 개발 도구 가이드

설정 기준: 2026-10-16. 제품 런타임과 분리된 Linux/macOS/WSL 개발 환경용이다. Windows에서는 WSL을 사용한다. Node 24, Python 3.12, uv, GNU Make, Git이 필요하며 plugin 설치에는 `codex plugin`을 지원하는 Codex CLI가 필요하다. 직접 버전과 Git ref는 [versions.mk](../tools/versions.mk)에 고정했다. 하위 의존성은 upstream에서 관리하므로 전체 dependency lock을 보장하지 않는다.

## 역할과 설치 범위

| 도구 | GhostManual에서의 역할 | 구성 |
|---|---|---|
| [Superpowers](https://github.com/obra/superpowers) | 설계·구현·검증 절차 | `plugins`로 사용자 Codex에 설치 |
| [PM Skills](https://github.com/phuryn/pm-skills) | 발견·전략·시장·분석·출시·실행 | `plugins`로 9개 plugin 전체 설치 |
| [Ponytail](https://github.com/DietrichGebert/ponytail) | 기존 코드 재사용·변경 간소화·리뷰 | `plugins`로 설치, 검증·보안은 유지 |
| [LazyCodex](https://github.com/code-yeongyu/lazycodex) | 선택한 작업의 대체 오케스트레이션 | 별도 `lazycodex` target, 기본 설치와 분리 |
| [CodeGraph](https://github.com/colbymchenry/codegraph) | 로컬 코드 그래프·MCP 탐색 | `install-core`, `index`, `.codex/config.toml` |
| [Iron Laws](https://github.com/JinHo-von-Choi/iron-laws) | 정적 보안·구조 검사 | `install-core`, `check`·`report`, PR workflow |
| [Strix](https://github.com/usestrix/strix) | 수동 AI 보안 검사 | `install-optional`, `strix`, 수동 workflow |
| [OmniRoute](https://github.com/diegosouzapw/OmniRoute) | 개발 도구의 모델 게이트웨이 | `install-optional`, `gateway` |
| [Headroom](https://github.com/headroomlabs-ai/headroom) | 개발 요청의 문맥 압축 프록시 | `install-optional`, `headroom` |

이 설정은 제품의 OpenAI 제공자·모델·`AI_ENABLED`를 바꾸지 않는다. Superpowers를 기본 절차로 사용하고 LazyCodex의 계획·검증 루프는 같은 작업에 중복 적용하지 않는다. 사용자·저장소 지시가 plugin 기본값보다 우선한다.

## 설치와 CodeGraph

저장소 루트에서 실행한다. Makefile 절대 경로를 주면 다른 디렉터리에서도 실행할 수 있다.

```bash
make -f tools/Makefile help
make -f tools/Makefile install       # 전체 CLI, .dev-tools/ 안에 격리
# 작은 설치부터 시작하려면: make -f tools/Makefile install-core
make -f tools/Makefile index         # .codegraph/ 생성
make -f tools/Makefile doctor
```

CodeGraph와 OmniRoute는 서로 다른 npm prefix에, Python 도구는 전용 venv에 설치한다. 앱의 package.json·lockfile은 변경하지 않는다. 설치 과정의 npm peer dependency 경고는 upstream 의존성의 상태이며 실행 검증과 구분한다. npm이 lifecycle scripts 허용을 요구하면 upstream README의 허용 목록을 확인한다. 제공한 목록을 모르는 npm 버전은 unknown cli config 경고를 낼 수 있다.

Codex에서 이 프로젝트를 신뢰한 후 새 채팅을 열면 [프로젝트 MCP 설정](../.codex/config.toml)을 읽는다. `npx`가 실행 PATH에 있어야 하며 최초 실행은 registry 접속이 필요하다. graph와 버전 변경 후에는 `index`를 실행한다. 다른 MCP 클라이언트에서는 `codegraph serve --mcp`를 stdio 서버로 연결한다. 자동 인덱스 갱신은 MCP가 실행 중일 때 동작한다.

## Codex 스킬·플러그인

```bash
make -f tools/Makefile plugins
# 선택 사항: Superpowers 대신 LazyCodex 흐름을 쓸 때만 설치
make -f tools/Makefile lazycodex
codex plugin list
```

`plugins`·`lazycodex`는 **사용자 Codex 설정**에 설치하므로 다른 프로젝트에도 보인다. Git ref로 marketplace를 고정하며, 업데이트하려면 versions.mk를 검토해서 바꾸고 재설치한다. 연결된 Codex 앱의 기존 plugin과 이 CLI의 설치 경로는 서로 다를 수 있다. 이 클라우드 환경에서 설치한 plugin이 사용자 PC에 자동 설치되지는 않는다.

설치 후 새 채팅에서 skill을 확인한다. PM Skills의 Claude slash command는 Codex slash command로 그대로 동작하지 않으므로 원하는 기획 작업을 자연어로 요청한다. Ponytail lifecycle hooks는 Codex `/hooks`에서 내용을 확인하고 신뢰해야 동작한다. 이 설정은 hook 신뢰·sandbox·승인 정책을 자동 변경하지 않는다.

LazyCodex는 upstream의 실험적 marketplace 경로를 사용한다. upstream 기본 npx 설치 경로가 필요한 경우 README를 따른다. `--codex-autonomous`는 이 구성에서 실행하지 않는다. 기본 모델·권한을 자동 전환하지 않는다.

## Iron Laws

```bash
make -f tools/Makefile check
make -f tools/Makefile report        # .dev-tools/reports/iron-laws.md
# 원문 전체를 외부 AI로 보내지 않고 로컬에서 수정 지시문 생성
.dev-tools/venv/bin/iron-laws fix-prompt .
```

[설정](../.iron-laws.yml)은 생성물만 제외하며 규칙을 일괄 비활성화하지 않는다. 종료 0은 기준 통과, 1은 기준 미달, 2는 실행·입력 오류다. 지적이 있어도 `fix-prompt`는 성공 종료할 수 있으므로 check의 대용으로 쓰지 않는다.

[Iron Laws workflow](../.github/workflows/iron-laws.yml)는 PR에서 base SHA 이후 **변경된 파일 전체**를 검사한다. 변경 줄만 검사하거나 변경되지 않은 호출자까지 분석한다는 뜻은 아니다. 새 지적과 기존 지적이 같은 변경 파일에 있으면 모두 판정한다. 수동 실행은 저장소 전체를 검사한다. 발견이나 실행 오류를 `|| true`로 숨기지 않는다. 비밀과 유료 LLM 없이 실행한다.

현재 upstream은 검사할 파일이 없는 범위에서도 종료 2를 반환한다. 이미지·제외 파일·삭제만 있는 PR은 이 제한으로 점검이 실패할 수 있다. 오류를 정상 통과로 바꾸는 예외 처리는 추가하지 않았다. 초기 실행에서는 tsconfig 경로 별칭 해석 경고도 남았으므로 파일 간 분석이 완전하다고 보지 않는다.

첫 전체 점검에는 기존 CI용 합성 자격증명, lockfile의 무결성 문자열, 요청 헤더로 세션 쿠키를 선택하는 코드 등에 HIGH 이상 지적이 있었다. `requestSession`은 헤더를 역할 권한으로 저장하지 않고 `requireSession`이 서버 DB의 토큰 해시·역할·만료·공유 취소를 검증한다. 이들은 검토가 필요한 scanner 결과이며 실제 비밀 유출·권한 우회 확정으로 보지 않는다. 이번 구성에서 baseline이나 suppression으로 숨기지 않았다. 전체 검사가 실패할 수 있으며 실제 수치·검증은 진행 기록을 따른다.

## Strix

Docker와 사용 가능한 LLM 계정·예산이 필요하다. 키는 secret manager나 로컬 shell 환경으로 전달하고 채팅·파일·Git에 붙이지 않는다.

```bash
# shell에 STRIX_LLM과 제공자 인증을 안전하게 설정한 뒤:
make -f tools/Makefile strix
```

로컬 target은 `git archive HEAD`로 만든 마지막 커밋 스냅샷이다. 미커밋 변경·`.env`·도구 캐시는 포함하지 않는다. snapshot은 `.dev-tools/strix-source.*`, 결과는 `strix_runs/`에 남는다. 검토할 변경을 커밋한 뒤 실행한다. LLM에는 분석 코드가 전달될 수 있으므로 합성 자료만 사용한다. 외부 운영 서비스는 이 target의 검사 대상이 아니다.

[수동 Strix workflow](../.github/workflows/strix.yml)는 GitHub repository secrets `STRIX_LLM`, `LLM_API_KEY`, 필요하면 `LLM_API_BASE`를 사용한다. 모델 ID와 계정은 사용자가 연결한다. secrets 없이 실행하면 명확히 실패한다. PR에서 자동으로 유료 검사를 실행하지 않는다. HIGH 이상을 실패로 처리하고 30분 timeout을 둔다. 실제 비용 상한은 제공자 계정에서 설정한다.

수동 workflow는 콘솔 로그만 보존하고 `strix_runs/`를 artifact로 업로드하지 않는다. 상세 결과 파일을 보관하려면 로컬 target을 사용한다. runner 종료 후 상세 보고서는 사라지는 제한이 있다.

새 workflow는 기본 브랜치에 반영된 후 Actions 수동 실행 목록에 표시된다. 기존 테스트 CI와 배포 절차는 별도로 유지한다.

## OmniRoute·Headroom

각 명령은 foreground로 실행되며 종료는 해당 터미널에서 Ctrl+C다.

```bash
make -f tools/Makefile gateway       # 127.0.0.1:20128
make -f tools/Makefile headroom      # 127.0.0.1:8787
```

OmniRoute dashboard에서 본인 제공자 계정과 API key를 연결하고 endpoint key를 만든다. 무료 한도는 각 제공자의 가입 자격·약관·잔여량에 따른다. 먼저 개발 도구 한 개에서 OpenAI 호환 endpoint `http://127.0.0.1:20128/v1`을 명시적으로 선택한다. gateway는 `DATA_DIR=.dev-tools/gateway-data`와 `OMNIROUTE_SERVER_HOST=127.0.0.1`을 사용한다. 프로젝트 앱의 `.env`를 읽지 않도록 별도 작업 디렉터리에서 실행하며 설치 패키지 `.env`도 건너뛴다. upstream이 기존 사용자 기본 환경 파일을 참조할 수 있으므로 기존 `~/.omniroute/.env`가 있으면 설정 우선순위를 확인한다. 키와 상태는 Git에 넣지 않는다.

Headroom은 telemetry를 끄고 stateless·구조적 압축(`--disable-kompress`)으로 시작한다. 모델 다운로드와 cross-agent 영구 메모리는 기본 실행 경로에 포함하지 않는다. 선택한 개발 클라이언트에서 `http://127.0.0.1:8787/v1`을 사용하고 정상 요청·토큰·품질을 비교한다. `headroom wrap codex`는 Codex 설정을 수정하므로 자동 실행하지 않는다. 별도로 사용했다면 `headroom unwrap codex`로 복구한다.

처음에는 둘 중 한 경로만 사용한다. OmniRoute 압축과 Headroom 압축을 중첩하지 말고, 프록시 연쇄가 필요하면 upstream 모델·API 호환성과 오류·품질·비용을 별도 검증한다. 설치나 health 응답만으로 실제 LLM 요청 성공을 주장하지 않는다.

## 복구와 배포

`.dev-tools/`, `.codegraph/`, `strix_runs/`는 로컬 산출물이며 Git·Biome·Docker 빌드에서 제외한다. 도구 제거 시 필요한 보고서를 먼저 보존하고 해당 로컬 디렉터리만 삭제한다. 사용자 plugin은 `codex plugin remove <plugin>@<marketplace>`로 개별 제거하고, 기존에 사용하던 설치를 무작정 제거하지 않는다. MCP를 제거하려면 `.codex/config.toml`의 codegraph 항목을 제거한다.

AWS의 작은 운영 서버에서 도구를 상시 실행하지 않는다. 이 변경은 서비스 배포·DNS·운영 DB를 변경하지 않는다.
