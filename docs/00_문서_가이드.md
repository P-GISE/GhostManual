# 문서 가이드

현재 저장소는 개발 도구와 빈 프로젝트 가이드만 남긴 초기 상태다. 제품 범위·기술·기능·DB·API·배포는 아직 정하지 않았다.

## 시작 순서

1. [작업 지침](AGENTS.md)을 읽고 [프로젝트 맥락](PROJECT_GUIDE.md)에 새 요구사항을 정리한다.
2. [99 작업 목록](99_해야할일.md)에 작업과 완료 조건을 정한다.
3. 01 시스템 → 02 기능 → 관련 설계 문서 순서로 구체화한다.
4. 실제 검증 결과를 [10 점검 현황](10_파일_점검_현황.md)에 기록하고 99 상태를 갱신한다.

## 문서별 담당

01=목적·범위·시스템, 02=기능·인수 조건, 03=DB, 04=API, 05=업무 흐름, 06=프런트, 07=백엔드, 08=운영·배포, 09=위험·개선, 10=확인·검증, 99=할 일이다.
전체 파일은 [프로젝트 가이드 목록](README.md)에서 찾는다.

## Superpowers 사용

새 기능과 동작은 brainstorming으로 요구·범위를 정리하고, 다단계 구현은 writing-plans 후 승인된 실행 방식으로 진행한다. 버그는 systematic-debugging으로 원인을 확인한다. 구현에는 관련 회귀 검증과 verification-before-completion을 적용한다. 도구 설치는 [개발 도구 가이드](개발_도구_가이드.md)를 따른다.

## 기록 규칙

미작성·제안·구현·검증을 구분한다. 테스트·빌드·배포 결과는 실제 명령·종료 코드·대상 commit·환경을 확인한 경우만 기록한다. 과거 이력을 새 작업의 완료 근거로 복사하지 않는다. 비밀·토큰·실제 업무 원문을 문서에 기록하지 않는다.
