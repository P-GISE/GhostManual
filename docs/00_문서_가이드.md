# 문서 가이드

현재 저장소에는 개발 도구와 프로젝트 가이드가 있다. GhostManual은 PC 화면·여러 앱의 업무 과정을 자동 수집해 인수인계 매뉴얼을 만드는 방향으로 재기획 중이다. 제품 기획·PoC·개념 ERD와 01~07은 검토용 초안이며 제품 코드·DB·실험 결과는 없다.

## 시작 순서

1. [작업 지침](AGENTS.md)을 읽고 [프로젝트 맥락](PROJECT_GUIDE.md)에 새 요구사항을 정리한다.
2. [99 작업 목록](99_해야할일.md)에 작업과 완료 조건을 정한다.
3. 01 시스템 → 02 기능 → 관련 설계 문서 순서로 구체화한다.
4. 실제 검증 결과를 [10 점검 현황](10_파일_점검_현황.md)에 기록하고 99 상태를 갱신한다.

## 현재 작성 상태

작업 맥락·절차·개발 환경·제약·확인 근거·다음 작업은 이 문서와 PROJECT_GUIDE·08·09·10·99에 기록한다. 제품 설계인 01~07은 확인된 자동 수집형 목적과 PC 수집 범위를 기준으로 초안을 작성했다. 첫 OS는 Windows로 사용자 확인됐다. 대표 업무는 웹 자료 조회→Excel 정리→결과 문서 작성으로 확인됐다. 수치 목표·제품 기술·실험 조건은 검토 후 확정한다. 단계가 바뀌면 해당 문서와 99 상태를 함께 갱신한다.

01=목적·범위·시스템, 02=기능·인수 조건, 03=DB, 04=API, 05=업무 흐름, 06=프런트, 07=백엔드, 08=운영·배포, 09=위험·개선, 10=확인·검증, 99=할 일이다.
전체 파일은 [프로젝트 가이드 목록](README.md)에서 찾는다.

## Superpowers 사용

새 기능과 동작은 brainstorming으로 요구·범위를 정리하고, 다단계 구현은 writing-plans 후 승인된 실행 방식으로 진행한다. 버그는 systematic-debugging으로 원인을 확인한다. 구현에는 관련 회귀 검증과 verification-before-completion을 적용한다. 도구 설치는 [개발 도구 가이드](개발_도구_가이드.md)를 따른다.

## 기록 규칙

미작성·제안·구현·검증을 구분한다. 테스트·빌드·배포 결과는 실제 명령·종료 코드·대상 commit·환경을 확인한 경우만 기록한다. 과거 이력을 새 작업의 완료 근거로 복사하지 않는다. 비밀·토큰·실제 업무 원문을 문서에 기록하지 않는다.

## 검증 선택

문서 변경은 파일 존재·내부 링크·diff 검사를 수행한다. 개발 도구 변경은 관련 CLI·설정·workflow를 검증한다. 제품 구현 후에는 해당 기술과 인수 조건에 맞는 회귀·통합·화면·배포 검사를 정한다. 현재 package.json과 제품 테스트가 없으므로 npm test/build 명령을 있다고 가정하지 않는다.

## 기록 형식

99: 작업 ID·우선순위·내용·주관/연결 문서·상태·선행 조건·완료 조건/근거.
10: 확인 날짜·대상 파일/영역·기준 commit/작업 트리·실행 명령·종료 코드/결과·미검증 범위.

상태는 대기·진행·차단·검증 대기·완료·보류로 표시한다. 명시적 계정·접근·결정이 필요한 차단은 그 조건을 함께 적는다.
